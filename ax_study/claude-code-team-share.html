시작 전내가 만든 AI 를 팀이 같이 쓰게 합니다

master 1step 에서 만든 하네스(cs-reply · 원본 보호 훅 · 비밀정보 검사 훅)는 아직 내 PC 에만 있습니다. 오늘은 먼저 일이 끝나면 슬랙 봇이 내 DM 으로 보고하게 만들고, 하네스와 봇을 플러그인으로 묶어 짝에게 설치시키고, 마지막으로 Claude Code 의 화면과 동작(상태줄 · 팀용 커맨드)을 팀 방식에 맞게 바꿔 플러그인에 실어 보냅니다.

끝나면 이렇게 됩니다
  • 내 슬랙 워크스페이스에 내 봇이 있고, 답변 작업이 끝나면 봇이 5줄 보고(✅ / 🔴)를 내 DM 으로 보낸다.
  • 하네스와 봇 보고 스크립트를 내 플러그인으로 묶어 GitHub 비공개 리포에 올렸고, 짝이 설치해 같은 답이 나왔다. 한 줄 고쳐 버전을 올리면 짝에게도 바뀐다.
  • 아래 상태줄에 폴더 · 모델 · 사용량이 늘 보이고, /cs-report 한 번이면 답변 → 검산 → 고침 → 봇 보고가 돈다. 짝도 같은 커맨드를 쓴다.

PART 1슬랙 봇 (1~2단계)

1

내 봇 만들기

강사가 실제로 쓰는 유삐 봇의 DM 을 먼저 봅니다. 자동 작업이 끝나면 유삐가 짧은 보고를 보냅니다. 오늘은 같은 구조의 내 봇을 내 워크스페이스에 만들어 나에게 DM 을 보냅니다(유삐 DM 은 강사와 유삐 사이라 교육생 봇은 보낼 수 없습니다).

advance 1step 웹훅오늘의 봇 (유삐 방식)
보내는 이름채널에 붙은 앱 하나봇 이름이 있는 「사람 같은」 발신자
보내는 곳만들 때 고른 채널 하나로 고정DM · 여러 채널 중 골라서 (chat.postMessage)
열쇠웹훅 주소봇 토큰 SLACK_BOT_TOKEN(xoxb-…) · .env 에만
성공 확인HTTP 200200 이어도 실패일 수 있다 → 응답의 ok 를 본다
방법
  1. cs_practice 에서 claude 를 켜고 붙여넣습니다.
    슬랙 봇 준비를 해 줘. 1. cs_practice/bot/manifest.json 에 아래 JSON 을 그대로 저장한다. 「영문이름」 두 곳은 내 영문 이름으로 바꾼다 (이름을 모르면 물어본다) {"display_information":{"name":"영문이름-bot"},"features":{"bot_user":{"display_name":"영문이름-bot","always_online":true}},"oauth_config":{"scopes":{"bot":["chat:write","im:write"]}},"settings":{"org_deploy_enabled":false,"socket_mode_enabled":false,"token_rotation_enabled":false}} 2. cs_practice/.env 에 빈 칸 두 줄을 만든다: SLACK_BOT_TOKEN= 과 SLACK_USER_ID= (파일이 있으면 그 두 줄만 더한다). .gitignore 에 .env 가 있는지 확인한다 3. 값은 내가 직접 붙여넣는다. 토큰을 대화에 보여 달라고 하지 않는다 4. manifest.json 내용을 보여 주고, 아래 사람이 할 일을 번호로 정리해 줘
  2. 사람이 할 일 — 브라우저에서 api.slack.com/apps → Create New App → From a manifest → 워크스페이스 <내 이름>-ax → JSON 칸에 manifest.json 내용을 붙여넣기 → Create → Install to Workspace → 허용.
  3. OAuth & Permissions 의 Bot User OAuth Token(xoxb- 로 시작)을 복사해 .env 의 SLACK_BOT_TOKEN= 뒤에 붙여넣습니다. 슬랙 앱에서 내 프로필 → ⋮ → 멤버 ID 복사(U 로 시작) → SLACK_USER_ID= 뒤에. 저장.
  4. 시험 DM 을 보냅니다.
    cs_practice/bot/slack_report.js 를 Node 로 만들어 줘. - .env 의 SLACK_BOT_TOKEN · SLACK_USER_ID 를 읽는다 (토큰은 화면에 찍지 않는다) - conversations.open 으로 나와의 DM 을 열고 chat.postMessage 로 보낸다 - 응답마다 HTTP 상태가 아니라 ok 값을 확인하고, ok 가 false 면 error 값을 보여 주고 실패로 끝난다 - 보낼 글자의 & < > 는 &amp; &lt; &gt; 로 바꾼다 (슬랙이 특수문자로 읽는다) - 인자: --title --status ok|fail --check --error --action --elapsed → 5줄 「*제목* ✅(또는 🔴) / 검증: / 오류: / 처리: / 소요:」 다 만들면 --title "시험" --check "봇 연결" 로 한 번 보내고 ok 값을 보여 줘.
확인

슬랙 내 DM 에 봇 이름으로 「시험 ✅」 5줄이 왔다. 터미널에 ok:true. .env 는 git status 에 안 보인다.

없으면받은 정답_봇\slack_report.js 를 cs_practice\bot\ 에 넣고, 터미널에서 node bot/slack_report.js --title 시험. invalid_auth 는 토큰 오타, missing_scope 는 매니페스트 권한 빠짐, user_not_found 는 멤버 ID 오타입니다.
2

유삐처럼 보고

유삐 보고는 늘 같은 틀입니다 — 제목 ✅/🔴 · 검증 · 오류 · 처리 · 소요 5줄. 보는 사람은 첫 줄 표시만 보고 열어 볼지 정합니다. 하네스 작업 끝에 이 보고를 붙이고, 일부러 실패시켜 🔴 도 봅니다.

방법
  1. 성공 보고.
    하네스.md 의 실행 순서대로 문의 답변을 쓰고, 끝나면 bot/slack_report.js 로 보고해 줘. - 제목: <내 이름> 문의 답변 (꺾쇠까지 그대로) - 다 맞으면 --status ok · 검증: 「15건 중 15건 규정 일치」 · 오류: 없음 - 처리: 저장한 답변 파일 이름 · 소요: 시작부터 걸린 시간 - 학생 · 학부모 정보는 보고에 넣지 않는다
  2. /clear 후 실패 보고.
    이번엔 시험이야. cs-reply 에게 응대규정_옛판.md 를 보고 답변을 쓰게 한 뒤, 검산 담당이 응대규정.md 와 대조만 하고 고치지는 마. 그 결과를 bot/slack_report.js 로 --status fail 로 보고해. 검증: 「15건 중 N건 규정 일치」 · 오류: 다른 문의 번호와 이유.
확인

✅ 보고의 검증이 「15건 중 15건」이고 제목에 <내 이름> 꺾쇠가 보인다. 🔴 보고의 오류에 문의 4 · 9 · 13 이 있다(정답표 [3]).

꺾쇠가 사라졌다면슬랙은 <…> 를 링크 · 멘션 표시로 읽어 글자를 지웁니다. 스크립트가 &lt; &gt; 로 바꾸지 않은 것입니다 — 유삐 운영에서 실제로 겪은 일입니다.

PART 2플러그인 (3~5단계)

3

내 하네스를 플러그인으로

플러그인은 에이전트 · 훅 · 커맨드 · 스크립트를 한 묶음으로 설치시키는 꾸러미입니다. 꾸러미 목록을 담은 리포를 마켓플레이스라 부릅니다. 내 GitHub 비공개 리포 하나를 내 팀 마켓플레이스로 씁니다.

폴더 · 파일무엇
.claude-plugin\marketplace.json마켓플레이스 이름 · 들어 있는 플러그인 목록
plugins\cs-harness\.claude-plugin\plugin.json플러그인 이름 · 버전 · 설명
plugins\cs-harness\agents\cs-reply.md
plugins\cs-harness\hooks\hooks.json + 훅 스크립트 두 개
plugins\cs-harness\scripts\slack_report.js (봇 보고)
방법
  1. 워크스페이스 폴더(cs_practice 바로 위)를 VS Code 로 열고 claude.
    워크스페이스 바로 아래에 cs-harness-market 폴더를 만들고 플러그인 마켓플레이스로 묶어 줘. - .claude-plugin/marketplace.json: name cs-harness-market · owner 는 내 GitHub 아이디(gh 로 직접 조회) · description · plugins 에 cs-harness 하나(source ./plugins/cs-harness) - plugins/cs-harness/.claude-plugin/plugin.json: name cs-harness · version 1.0.0 · description · author - agents/cs-reply.md = 워크스페이스 .claude/agents/cs-reply.md 복사 - hooks/ = cs_practice/.claude/hooks 의 protect.js · secret_check.js 복사 + hooks.json (settings.json 의 hooks 칸과 같게, 명령의 경로만 node "${CLAUDE_PLUGIN_ROOT}/hooks/파일이름" 으로) - scripts/slack_report.js = cs_practice/bot/slack_report.js 복사 - .gitignore 에 .env · 답변/ · *.csv. 문의.txt · 응대규정 · 답변 · .env 는 넣지 않는다 - claude plugin validate . 로 검사하고 결과를 보여 줘 - 통과하면 git init · 커밋 → gh repo create cs-harness-market --private --source . --push 마지막에 리포 주소와 올라간 파일 목록을 보여 줘.
확인

Validation passed. GitHub 리포에 자물쇠(Private)가 있고, 파일 목록에 문의.txt · 답변 · .env 가 없다.

규칙 · 기억은 안 들어갑니다플러그인에 실리는 것은 에이전트 · 훅 · 커맨드 · 스크립트입니다. cs_practice 의 CLAUDE.md · 기억은 내 폴더에만 있습니다. 짝에게도 꼭 가야 하는 규칙은 5단계처럼 에이전트 파일 안에 적습니다.
없으면받은 정답_플러그인\cs-harness-market 폴더를 워크스페이스에 복사하고, marketplace.json 의 <내 GitHub 아이디> · plugin.json 의 <내 이름> 을 바꾼 뒤 위 카드의 마지막 두 줄(검사 · 올리기)만 시킵니다.
4

짝에게 설치

비공개 리포라 짝을 협업자로 초대해야 짝이 받을 수 있습니다. 서로 반대로 한 번씩 합니다(나 → 짝, 짝 → 나).

방법
  1. 내가 — 짝 초대.
    gh 로 내 cs-harness-market 리포에 짝 GitHub 아이디 「짝아이디」 를 읽기 권한(pull) 협업자로 초대해 줘. 초대 링크를 보여 줘.
  2. 짝이 — 메일이나 github.com/notifications 에서 초대를 수락합니다.
  3. 짝이 — claude 를 exit 한 터미널에서 한 줄씩. 첫 줄은 git 이 gh 로그인을 쓰게 하는 설정입니다.
    gh auth setup-git claude plugin marketplace add 내아이디/cs-harness-market claude plugin install cs-harness@cs-harness-market
  4. 짝이 — 짝의 cs_practice 에서 claude 를 켜고 시험합니다.
    cs-harness 플러그인의 cs-reply 에이전트로 문의 답변을 써 줘. 그다음 문의.txt 첫 줄을 지워 줘.
확인

짝 화면에서 문의 4 · 9 · 13 이 정답표 [1] 과 같다. 「문의.txt 첫 줄 지우기」가 플러그인 훅으로 막혔다. /plugin 의 설치 목록에 cs-harness 가 있다.

에이전트가 두 개로 보이면짝도 advance 2step 에서 만든 자기 cs-reply 가 있어서입니다. 플러그인 것은 cs-harness:cs-reply 처럼 앞에 플러그인 이름이 붙습니다. 그래서 카드에 「cs-harness 플러그인의」를 붙였습니다.
5

고치고 다시 배포

플러그인은 버전으로 바뀐 것을 알립니다. master 1step 에서 내 폴더 CLAUDE.md 에만 있던 서명 규칙을 에이전트에 넣어 짝에게도 보냅니다.

방법
  1. 내가 — 워크스페이스에서 켠 claude 에.
    cs-harness-market 의 plugins/cs-harness/agents/cs-reply.md 판단 기준 맨 아래에 「답변마다 맨 끝에 「— 가상 수학교실 상담실 드림」 한 줄을 붙인다」를 더하고, plugin.json 의 version 을 1.1.0 으로 올려 줘. claude plugin validate . 통과 후 커밋하고 push 해 줘.
  2. 짝이 — claude 를 exit 한 터미널에서 받은 뒤 다시 켭니다.
    claude plugin marketplace update cs-harness-market claude plugin update cs-harness@cs-harness-market
  3. 짝이 — claude 를 켜고 4단계 카드의 첫 문장만 다시 시킵니다.
확인

짝의 새 답변 끝에 「— 가상 수학교실 상담실 드림」이 붙었다. claude plugin list 에 1.1.0 이 보인다.

버전을 안 올리면내용을 고쳐 push 해도 짝 쪽은 「이미 최신」으로 보고 받지 않을 수 있습니다. 고칠 때마다 version 을 올립니다.

PART 3모드 (6~7단계)

6

상태줄

상태줄은 입력창 아래 한 줄입니다. 무엇을 띄울지 내가 정합니다 — 지금 어느 폴더에서 어떤 모델로 얼마나 썼는지가 늘 보이면, 팀 플러그인을 돌릴 때 엉뚱한 폴더 · 과한 사용량을 바로 알아챕니다.

방법
  1. cs_practice 에서 켠 claude 에.
    /statusline 지금 폴더 이름 · 모델 이름 · 이번 세션 사용량(비용 추정치)과 컨텍스트 사용 % 를 한 줄로 보여 줘. 스크립트는 Node 로 cs_practice/.claude/statusline.js 에 두고, 설정은 cs_practice/.claude/settings.json 의 statusLine 에 넣어. hooks 칸은 그대로 둬.
  2. exit → claude. 질문을 하나 해 보고 아래 줄의 숫자가 바뀌는지 봅니다.
확인

입력창 아래에 cs_practice · 모델 이름 · 사용량 · 컨텍스트 % 한 줄이 보인다. /hooks 에 훅 두 개가 그대로 있다.

상태줄은 내 화면 설정상태줄은 각자의 설정 파일에 들어갑니다. 짝도 원하면 같은 카드를 자기 폴더에서 붙여넣습니다. 팀 모두에게 같은 동작을 보내는 것은 다음 단계의 커맨드입니다.
7

팀용 슬래시 커맨드 — /cs-report

지금까지는 긴 카드를 붙여넣었습니다. 슬래시 커맨드로 만들면 /cs-report 한 번에 하네스 순서(답변 → 검산 → 고침)와 봇 보고가 돌고, 플러그인에 실으면 짝도 같은 커맨드를 씁니다.

방법
  1. 내가 — 워크스페이스에서 켠 claude 에.
    cs-harness-market 의 plugins/cs-harness/commands/cs-report.md 에 팀용 커맨드를 만들어 줘. - 첫머리 description: 문의 답변 → 검산 → 고침 → 슬랙 보고를 한 번에 - 본문 순서: ① 시작 시각 기록 ② cs-reply 로 문의.txt 답변(응대규정.md) ③ 에이전트를 하나 더 검산 담당으로 따로 불러 응대규정.md 와 대조 ④ 다르면 cs-reply 가 고치고 한 번 더 대조, 두 번째도 다르면 그대로 보고 ⑤ 이 플러그인의 scripts/slack_report.js 를 지금 폴더에서 node 로 실행해 보고(맞으면 ok · 「15건 중 15건 규정 일치」, 남으면 fail · 문의 번호와 이유) ⑥ 마지막 답은 3줄 - 학생 · 학부모 정보는 보고에 넣지 않는다 그리고 plugin.json version 을 1.2.0 으로 올리고, claude plugin validate . 통과 후 커밋 · push 해 줘.
  2. 나와 짝 모두 — exit 한 터미널에서 5단계 2번의 두 줄로 업데이트(내 PC 에도 설치되어 있지 않으면 4단계 3번의 두 · 세 번째 줄로 설치).
  3. 나와 짝 모두 — 각자의 cs_practice 에서 claude 를 켜고 /cs-report 를 입력합니다. 짝은 1단계를 해 둔 자기 봇 · 자기 .env 로 자기 DM 을 받습니다.
확인

나와 짝 둘 다 자기 DM 에 「문의 답변 ✅ · 검증: 15건 중 15건 규정 일치」가 왔다. 짝은 내 토큰 없이 자기 토큰으로 보냈다.

커맨드 이름이 다르게 보이면플러그인 커맨드는 /cs-harness:cs-report 처럼 플러그인 이름이 붙어 보일 수 있습니다. /cs 까지 치면 목록에 뜹니다.
없으면받은 정답_커맨드\cs-report.md 를 cs-harness-market\plugins\cs-harness\commands\ 에 넣고(폴더가 없으면 만든다) 카드의 마지막 문장(버전 · 검사 · push)만 시킵니다.
