시작 전사람이 매번 확인하지 않아도 지켜지게 만듭니다

지금까지는 사람이 매번 지시하고 결과를 확인했습니다. 오늘은 advance 2step 의 학부모 문의 답변을 그대로 쓰면서, Claude 가 기억하고(Auto Memory), 정해진 순간에 기계가 막고(훅), 이것들을 한 설계로 묶고(하네스), 끝 조건을 줘서 끝날 때까지 스스로 반복(루프)하게 만듭니다.

끝나면 이렇게 됩니다
  • Claude 가 스스로 적어 둔 기억 파일을 열어 보고, 틀린 기억을 찾아 지웠다. 꼭 지킬 것은 CLAUDE.md 로 옮겼다.
  • 훅 두 개를 붙였다 — 원본 파일을 고치려 하면 막히고, 열쇠가 든 파일을 커밋하려 하면 막힌다.
  • 규칙 · 기억 · 훅 · 검산을 한 장에 적은 하네스 설계표를 만들고, 같은 지시를 하네스 전 3회 · 후 3회 돌려 표로 비교했다.
  • 끝 조건 · 검증 · 최대 횟수가 있는 루프를 돌려, 맞으면 스스로 멈추는 것을 봤다.

PART 1기억 (1~2단계)

1

Auto Memory 보기

Auto Memory 는 Claude 가 대화 중에 알게 된 사실을 메모리 폴더(MEMORY.md 목차 + 파일 여러 개)에 스스로 적고, 다음에 켤 때 읽는 기능입니다. 폴더마다 따로 쌓입니다.

방법
  1. cs_practice 에서 켠 claude 에 붙여넣습니다.
    앞으로 이 폴더에서 문의 답변을 쓸 때는 답변마다 맨 끝에 「— 가상 수학교실 상담실 드림」 한 줄을 붙여 줘. 파일은 고치지 말고, 다음에 켤 때도 기억해 둬.
  2. exit → claude 로 새로 켠 뒤 물어봅니다.
    답변 끝에 붙이기로 한 한 줄이 뭐였지? 그걸 어느 파일에 기억해 뒀는지 전체 경로도 알려 줘. 파일은 고치지 마.
  3. /memory 를 입력해 메모리 화면을 봅니다. Auto Memory 가 켜져 있는지, 메모리 폴더 열기가 있는지 확인하고 Esc.
확인

새로 켠 창에서 「— 가상 수학교실 상담실 드림」을 말한다. 메모리 파일 위치(C:\Users\<내 이름>\.claude\projects\<폴더 경로>\memory\)를 안다.

기억을 못 하면/memory 에서 Auto Memory 가 꺼져 있으면 켜고 1번부터 다시 합니다. 회사 계정 설정으로 꺼져 있으면 강사 화면으로 보고 2단계로 넘어갑니다.
2

기억 정리 — 틀린 기억 지우기

기억은 Claude 가 쓰기 때문에 틀린 것도 쌓입니다. 일부러 틀린 사실(옛 판 규정)을 하나 기억시키고, 찾아서 지웁니다.

방법
  1. 틀린 기억 넣기 (현행 규정은 한 달 2회입니다).
    참고로 결석 보강은 한 달에 1번까지야. 파일은 고치지 말고 이것도 기억해 둬.
  2. exit → claude 로 새로 켜고 점검합니다.
    이 폴더에 대해 기억하고 있는 것을 전부 보여 줘. 그중 응대규정.md 와 다른 기억이 있으면 어느 줄이 규정 몇 번과 다른지 알려 줘. 아직 고치지 마.
  3. 틀린 기억은 지우고, 꼭 지킬 것은 규칙으로 옮깁니다.
    방금 찾은 틀린 기억(보강 한 달 1번)은 메모리에서 지워 줘. 그리고 답변 끝 서명 한 줄은 꼭 지켜야 하니 기억 대신 이 폴더 CLAUDE.md 에 규칙으로 옮기고 메모리에서는 지워. 바꾼 파일과 줄을 보여 줘.
확인

메모리에 「보강 1번」 줄이 없다. cs_practice\CLAUDE.md 에 서명 규칙이 있다. 아래 표의 차이를 한 줄로 말할 수 있다.

3

훅이 뭔지

훅은 「언제 · 무엇을」을 정해 두면 그 순간마다 기계가 실행하는 명령입니다. Claude 가 규칙을 잊어도 훅은 돕니다. starter 에서 받은 알림 훅(응답이 끝나거나 허락을 기다릴 때 알림)이 이미 써 본 훅입니다.

방법
내 전역 설정(~/.claude/settings.json)에 있는 훅을 보여만 줘. 고치지 마. 훅마다 「언제(이벤트) · 무엇을(명령)」 한 줄씩 정리해 줘.

자주 쓰는 이벤트 네 가지

이벤트언제예
PreToolUse도구 실행 전 — 여기서만 막을 수 있다원본 파일 수정 막기 · 커밋 전 검사 (오늘 4 · 5단계)
PostToolUse도구 실행 후저장한 파일 형식 검사
Stop응답이 끝났을 때starter 알림 훅
UserPromptSubmit내가 프롬프트를 보냈을 때질문에 오늘 날짜 붙이기
확인

알림 훅을 「언제 · 무엇을」 한 줄로 말할 수 있다(예: 응답 끝(Stop)에 알림 스크립트 실행).

훅 끄는 법 — 먼저 알아 둡니다훅이 잘못 짜이면 모든 수정이 막힐 수 있습니다. 그럴 땐 cs_practice\.claude\settings.json 을 메모장으로 열어 "hooks" 칸을 지우고 저장한 뒤 exit → claude. /hooks 를 입력하면 지금 켜진 훅 목록을 볼 수 있습니다.
4

원본 보호 훅

문의 · 규정 파일은 원본이라 답변을 쓰다가 고쳐지면 안 됩니다. 「고치지 마」는 부탁이지만, 훅은 실행 직전에 막습니다.

방법
  1. 훅 만들기.
    cs_practice 에 원본 보호 훅을 만들어 줘. - 파일: cs_practice/.claude/hooks/protect.js · 설정은 cs_practice/.claude/settings.json 의 hooks - 언제: PreToolUse · matcher 는 Edit|Write|MultiEdit|Bash|PowerShell - 무엇을: 문의.txt · 응대규정.md · 응대규정_옛판.md 를 고치거나 지우려 하면 exit 2 로 막고, 이유를 한국어 한 줄로 돌려준다. 읽기(열어 보기 · 복사해 오기)는 막지 않는다 - Node 로 쓴다(.bat · .ps1 은 쓰지 않는다). 설정의 명령은 node .claude/hooks/protect.js - 다른 설정과 전역 설정은 건드리지 않는다 만든 뒤 가짜 입력으로 「막힘 1번 · 통과 1번」을 직접 시험해서 결과를 보여 줘.

    파일 수정 허락 창이 뜨면 허용합니다.

  2. exit → claude 로 다시 켜고(설정은 켤 때 읽힌다) /hooks 로 훅이 보이는지 봅니다.
  3. 일부러 고쳐 보라고 시킵니다. 두 줄을 하나씩 — 사이에 /clear. 같은 대화로 이어 시키면 Claude 가 훅을 미리 알고 아예 시도하지 않아, 훅이 막는 것을 볼 수 없습니다.
    문의.txt 첫 줄을 지워 줘.
    PowerShell 명령으로 응대규정.md 내용을 비워 줘.
확인

두 번 다 「원본 보호: … 고칠 수 없습니다」로 막혔다. 문의.txt 를 열어 보면 첫 줄 「가상 학부모 문의 15건」이 그대로다.

없으면받은 정답_훅\protect.js 를 cs_practice\.claude\hooks\ 에, 정답_훅\settings.json 을 cs_practice\.claude\ 에 넣고(폴더가 없으면 만든다) exit → claude. 정답 settings.json 에는 5단계 훅 줄도 들어 있어 secret_check.js 도 같이 넣습니다.
5

비밀정보 검사 훅

advance 1step 에서 「GitHub 에는 코드만」을 배웠습니다. 사람이 깜빡해도 커밋 직전에 열쇠(웹훅 주소 · 토큰 · 키)를 잡아내게 합니다.

방법
  1. 훅 더하기.
    cs_practice 에 비밀정보 검사 훅을 더해 줘. - cs_practice 안에서 새로 git init 하지 않는다. 워크스페이스가 Git 저장소면(advance 1step) 그대로 쓰고, 아니면 워크스페이스에서 git init 한다. 워크스페이스 .gitignore 에 .env 와 cs_practice/답변/ 을 넣는다 - 파일: cs_practice/.claude/hooks/secret_check.js · 같은 settings.json 의 PreToolUse 에 matcher Bash|PowerShell 로 추가한다 (원본 보호 훅은 그대로 둔다) - git commit 명령일 때만 검사한다: 올라갈 파일(스테이징된 파일 + 같은 명령의 git add 로 들어갈 파일)에 .env 파일 · 슬랙 웹훅 주소(hooks.slack.com) · xoxb- 같은 토큰 · sk- 같은 키 모양이 있으면 exit 2 로 막고, 파일 이름과 이유를 한국어로 돌려준다 - Node 로 쓴다. 설정의 명령은 node .claude/hooks/secret_check.js 만든 뒤 가짜 입력으로 「막힘 1번 · 통과 1번」을 시험해서 보여 줘.
  2. exit → claude 로 다시 켜고, 가짜 열쇠로 시험합니다.
    가짜키.txt 파일에 SLACK_BOT_TOKEN=xoxb-1234567890-abcdefghij 한 줄을 쓰고, 이 폴더 파일을 전부 git add 해서 「시험」으로 커밋해 줘.
  3. 막힌 것을 보고 정리합니다.
    가짜키.txt 를 지우고, git log 에 가짜키.txt 가 들어간 커밋이 없는지 확인해 줘.
확인

커밋이 「비밀정보 검사: 커밋을 막았습니다. 가짜키.txt (슬랙 토큰)」로 막혔다. git log 에 가짜키.txt 가 없다.

이 훅이 지키는 범위Claude Code 의 훅이라 Claude 가 커밋할 때만 돕니다. VS Code 소스 제어에서 내가 직접 누른 커밋은 잡지 않습니다. 열쇠는 처음부터 .env 에만 두고 .gitignore 에 넣는 것이 먼저입니다.

번외 — 일하는 담당을 칸 화면으로 보기 (훅)

서브 에이전트 · 팀원은 따로 일해서 메인 화면에는 결과만 보입니다. 담당을 부르는 순간(PreToolUse · Agent)에 훅이 터미널 창을 하나 새로 열고, 담당마다 칸을 하나씩 더해 그 담당이 받은 말 · 읽고 쓴 파일 · 보낸 쪽지를 실시간으로 보여 주게 합니다. 이 화면은 보기 전용입니다. 지시는 지금처럼 메인 창에서 합니다.

칸에 찍히는 것뜻
✉ ← 메인담당이 받은 일(서브는 메인에게서만 받는다)
● Read(문의.txt) · ● Write(…)담당이 읽고 쓴 파일
✉ → policy · ✉ ← replier팀원끼리 직접 주고받은 쪽지(팀일 때만)
방법
  1. 받은 파일 넣기. <정답_훅 경로> 를 내려받은 정답_훅 폴더 위치로 바꿉니다.
    <정답_훅 경로> 의 agent_panes.js 와 pane.js 를 cs_practice/.claude/hooks/ 에 복사하고, 같은 폴더의 칸화면_설정.json 에 있는 PreToolUse 항목(matcher Agent|Task)을 cs_practice/.claude/settings.json 의 PreToolUse 에 더해 줘. 원본 보호 · 비밀정보 검사 훅은 그대로 둔다.
  2. exit → claude 로 다시 켜고 /hooks 에 Agent|Task 가 보이는지 봅니다.
  3. 서브 둘을 동시에 부릅니다.
    서브 에이전트 2개를 한 번에 띄워 줘. 1번(설명: 환불 문의 찾기)은 문의.txt 에서 환불 관련 문의 번호를, 2번(설명: 보강 문의 찾기)은 보강 관련 문의 번호를 찾아 돌려준다. 파일은 만들지 않는다.
확인

터미널 창이 새로 뜨고 파란 칸 「환불_문의_찾기」 · 초록 칸 「보강_문의_찾기」에 ✉ ← 메인 → ● Read(문의.txt) → 찾은 번호가 찍혔다. 다 보면 그 창은 닫아도 됩니다(일에는 영향 없음).

다른 업무에서도 쓰려면그 작업 폴더의 .claude\hooks\ 에 같은 두 파일을 넣고 같은 설정을 더합니다. 모든 폴더에서 쓰려면 두 파일을 ~/.claude/hooks/ 에 두고 전역 설정(~/.claude/settings.json)에 넣되, 명령은 node C:/Users/<내 이름>/.claude/hooks/agent_panes.js 처럼 전체 경로로 씁니다. 팀원에게 이름을 붙여 부르면(advance 2step 4단계) 칸 이름이 팀원 이름이 됩니다.
주의Windows Terminal 이 있어야 합니다(없으면 훅이 아무것도 하지 않고 일은 그대로 진행). 칸은 Claude Code 가 담당마다 남기는 기록 파일을 읽는데, 이 파일은 공개 기능이 아니라서 Claude Code 가 업데이트되면 칸이 비어 보일 수 있습니다. 이 훅은 아무것도 막지 않습니다(항상 통과).
③ 하네스 6~7단계 · 25분

PART 3하네스 (6~7단계)

6

하네스 설계표

하네스는 말에 채우는 마구처럼, AI 가 정해진 길로 가게 하는 장치 전체입니다. 오늘 만든 규칙 · 기억 · 훅에 advance 2step 의 검산 담당(서브)을 더해 한 장에 적습니다.

방법
cs_practice/하네스.md 에 하네스 설계표를 만들어 줘. - 표 한 장: 층 | 무엇 | 파일 위치 | 틀리면 - 규칙: 이 폴더 CLAUDE.md 의 줄들 - 기억: 지금 남아 있는 이 폴더의 기억 - 훅: 원본 보호 · 비밀정보 검사 - 검산: 답변을 쓴 뒤 에이전트를 하나 더 검산 담당으로 따로 불러 응대규정.md 와 문의마다 대조 → 다르면 cs-reply 가 고침 - 표 아래 「실행 순서」 네 줄: ① cs-reply 로 답변 ② 검산 담당이 대조 ③ 다르면 cs-reply 가 고치고 한 번 더 대조 ④ 결과 3줄 보고(검산 결과 · 파일 이름 · 고친 문의) - 그리고 이 폴더 CLAUDE.md 에 「문의 답변을 쓰라고 하면 하네스.md 의 실행 순서대로 한다」 한 줄을 더해 줘 바꾼 파일을 보여 줘.
확인

하네스.md 에 네 층 표와 실행 순서 네 줄이 있다. CLAUDE.md 에 서명 규칙과 하네스 줄이 있다.

7

전/후 3회 비교

한 번 맞았다고 믿지 않습니다. 같은 지시를 세 번 돌려 매번 같은지 봅니다. 「전」은 하네스가 없는 빈 폴더, 「후」는 오늘 만든 cs_practice 입니다.

방법
  1. 전 — 워크스페이스에 cs_off 폴더를 만들고 문의.txt · 응대규정.md · 응대규정_옛판.md 세 파일만 복사합니다(.claude · CLAUDE.md · 하네스.md 는 넣지 않음). VS Code 에서 cs_off 를 열고 claude. 아래를 세 번 붙여넣습니다 — 사이마다 /clear, N 은 1 · 2 · 3.
    문의.txt 에 답변을 써서 답변_전N.md 로 저장해 줘.
  2. 후 — cs_practice 로 돌아와 claude. 아래를 세 번(사이마다 /clear).
    문의 답변 써 줘.
  3. 여섯 개 답변 파일을 정답표 [1] 과 대조해 표를 채웁니다(메모장이나 종이에).
회차문의 4 · 9 · 13 = 정답표 [1]근거 줄서명 줄검산 결과 보고
전 1 · 2 · 3_ / 3_ / 3_ / 3_ / 3
후 1 · 2 · 3_ / 3_ / 3_ / 3_ / 3
확인

후 3회가 모두 정답표 [1] 과 같고, 답변의 근거 · 서명 줄과 마지막 보고의 검산 결과가 매번 있다(3/3). 원본 세 파일은 그대로다.

「전」도 맞을 수 있습니다비교할 것은 한 번 맞았나가 아니라 매번 같은 모양인가, 그리고 틀렸을 때 누가 잡아 주나입니다. 「전」은 옛 판을 읽어도 아무도 잡지 않습니다.
④ 루프 8단계 · 20분

PART 4루프 (8단계)

8

끝 조건이 있는 루프

/loop 는 같은 지시를 되풀이해 돌립니다. 간격을 주면(/loop 10m …) 그 간격마다, 빼면 Claude 가 스스로 간격을 정합니다. 시작 전에 세 가지가 있어야 합니다 — 끝 조건(언제 멈추나) · 검증(맞았는지 무엇으로 아나) · 최대 횟수(못 맞춰도 멈추는 선).

멈추는 법 — 시작 전에돌고 있을 때 Esc 를 누르고 「루프 멈춰」라고 보냅니다. 그래도 계속되면 exit. 루프는 회차마다 사용량을 씁니다. 끝 조건 · 최대 횟수 없이 돌리지 않습니다.
방법
  1. 일부러 틀린 답변 파일을 만듭니다.
    cs-reply 에이전트에게 이번에는 응대규정_옛판.md 를 보고 문의 답변을 써서 답변/루프.md 로 저장하게 해 줘. 검산은 하지 마.
  2. 루프를 겁니다(간격을 빼서 Claude 가 정하게).
    /loop 답변/루프.md 를 응대규정.md 와 문의마다 대조해서, 규정 내용이 다른 문의를 딱 한 건만 고쳐 저장하고 「N회차: 문의 X 고침 · 남은 수 Y」 한 줄을 남겨. 다른 문의가 없으면 「끝: 검산 일치 (N회차)」라고 쓰고 루프를 멈춰. 5회차가 되면 맞든 안 맞든 멈추고 남은 문의 번호를 보고해.

    회차 사이에 1분 남짓 쉬었다가 다시 돕니다. 끝날 때까지 기다리며 회차 줄을 적어 둡니다.

확인

회차 줄이 3~4개 찍히고 「끝: 검산 일치」에서 스스로 멈췄다. 답변\루프.md 의 문의 4 · 9 · 13 이 정답표 [1] 과 같다.

루프를 쓸 만한 일끝을 기계가 판정할 수 있는 일(검산 일치 · 테스트 통과 · 파일 도착)에만 씁니다. 「좋아질 때까지」처럼 끝을 사람이 판단해야 하는 일은 루프 대신 내가 한 번씩 봅니다.
