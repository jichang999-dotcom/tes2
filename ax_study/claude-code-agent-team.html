시작 전혼자 하던 일을 여러 AI 에게 나눠 봅니다

일을 여러 AI 에게 나눠 맡기는 방법은 두 가지입니다 — 서브 에이전트와 에이전트 팀. 오늘은 가상 학원의 학부모 문의 15건으로 두 방법을 직접 띄우고 다뤄 보고, 마지막 5단계에서 내 업무에는 무엇을 쓸지 고릅니다. 먼저 알아 둘 것 하나: 나눠 맡긴다고 결과가 더 똑똑해지지는 않습니다. 대부분의 일은 혼자(싱글)가 가장 싸고 빠릅니다.

끝나면 이렇게 됩니다
  • 응대 담당 에이전트를 만들고 업무 지시서(무엇을 · 어디에 저장 · 무엇을 보고 · 막히면)를 넣어 정식 담당으로 만들었다.
  • 서브 에이전트 셋을 띄워 일을 나눠 맡겼고, 맡길 때 필요한 정보는 맡기는 쪽이 챙겨 넘겨야 한다는 것을 직접 봤다.
  • 에이전트 팀을 켜서 팀원끼리 주고받는 쪽지를 보고, 팀원에게 직접 말을 걸어 보고, 끝나고 기능을 껐다.
  • 내 업무 하나를 싱글 / 서브 / 팀 중 어디에 맡길지 판단 순서 3단으로 이유와 함께 말할 수 있다.

일을 나누는 세 가지 — 상담실로 보면

Claude Code 에서는상담실로 보면
싱글 에이전트상담원 한 명이 문의함 세 개를 모두 열어 본다. 같은 학부모가 여기저기 물어본 것도 한눈에 보인다. 대신 양이 많으면 오래 걸린다.
서브 에이전트문의함을 상담원 셋에게 하나씩 나눠 준다. 동시에 하니 빠르지만, 상담원끼리는 말할 수 없다. 실장(메인)이 모아서 정리한다.
에이전트 팀상담원 셋이 나눠 맡되, 「이 학부모 그쪽에도 물어봤어요?」 하고 서로 직접 묻는다. 그만큼 말이 많아져 사용량이 가장 많다.
오늘의 순서1 · 2단계에서 보고 준비하고, 3단계에서 서브, 4단계에서 팀을 직접 써 봅니다. 3 · 4단계는 결과물의 좋고 나쁨이 아니라 어떻게 띄우고 · 무엇을 넘기고 · 어떻게 지켜보고 끄는지를 익히는 시간입니다. 어떤 업무에 쓰면 좋은지는 5단계에서 근거와 함께 정리합니다.

PART 1보기와 준비 (1~2단계)

1

강사 시연 — 나눠서 일하는 장면 보기

방법

강사가 완성된 서브 에이전트와 에이전트 팀을 차례로 돌립니다. 두 가지만 봅니다.

  • 누가 누구에게 말하나 — 서브는 검산 결과를 메인 Claude 가 받아 옮깁니다. 팀은 [참관] policy → replier 처럼 팀원끼리 직접 말합니다.
  • 말이 어떤 길로 오가나 — 서브는 [전달] 줄마다 메인을 거치고, 팀은 메인을 거치지 않습니다. 결과물보다 오가는 길을 봅니다(3 · 4단계에서 같은 길을 직접 만들어 봅니다).
확인

[참관] 줄이 무엇인지(팀원끼리 주고받은 메시지의 사본) 말할 수 있다.

2

응대 담당을 정식 에이전트로

여러 명에게 나누려면 먼저 한 명이 무엇을 맡는지가 분명해야 합니다. 학부모 문의에 답하는 응대 담당을 만들고 업무 지시서 네 칸을 넣어, 누가 불러도 같은 방식으로 일하는 정식 담당으로 만듭니다.

방법
  1. 받은 cs_practice 폴더를 워크스페이스 폴더(basic_data 가 있는 곳)에 넣습니다.
  2. VS Code(또는 Cursor)에서 [파일] → [폴더 열기] → cs_practice.
  3. 터미널에서 claude 를 켜고 붙여넣습니다.
    cs_practice 바로 위 폴더의 .claude/agents/cs-reply.md 에 학부모 문의 응대 담당 에이전트를 만들어 줘. - 이름: cs-reply · 설명: 학부모 문의에 규정대로 답변 초안을 쓰는 담당. 「문의 답변 써 줘」라고 할 때 쓴다 - 도구: Read, Glob, Grep, Write, Bash, PowerShell - 「## 업무 지시서」 칸에 네 줄을 넣는다 - 무엇을: cs_practice 의 문의.txt 15건에 응대규정.md 대로 답변 초안을 쓴다 - 어디에 저장: cs_practice/답변/답변_오늘날짜(YYYYMMDD).md. 같은 이름이 있으면 _v2, _v3 를 붙인다 (덮어쓰지 않는다) - 무엇을 보고: 마지막 답은 결론 3줄 + 파일 이름만 - 막히면: 추측해서 채우지 말고 「확인 필요: 이유」 한 줄로 끝낸다 - 규칙: 따로 말하지 않으면 응대규정.md 만 본다 · 문의마다 답변 아래에 「근거: 규정 N번」 한 줄 · 규정에 없는 약속(할인 · 예외)은 하지 않는다 저장한 뒤 파일 내용을 보여 줘.

    파일 수정 허락 창이 뜨면 허용합니다.

  4. exit → claude 로 다시 켠 뒤(새 에이전트 파일은 다시 켜야 읽힌다) 일을 시킵니다.
    cs-reply 에이전트를 불러서 업무 지시서대로 문의 답변을 쓰게 해 줘.
확인

에이전트 파일에 업무 지시서 네 줄이 있다. 답이 결론 3줄 + 파일 이름뿐이고, cs_practice\답변\ 에 답변 파일이 생겼다. 문의마다 「근거: 규정 N번」 줄이 있다. 답변 내용은 사람마다 달라도 괜찮습니다.

없으면받은 정답_응대담당.md 를 워크스페이스의 .claude\agents\cs-reply.md 로(폴더가 없으면 만든다) 넣은 뒤 exit → claude. 정답 파일에는 업무 지시서 칸이 이미 들어 있어 3번은 건너뜁니다.

PART 2나누기 (3단계)

3

서브 에이전트 — 띄우기 · 맡기는 법

이번 문의 15건은 담당 A(수강료 · 휴원 · 형제 할인) · B(보강 · 반 변경) · C(교재 · 차량) 세 파일에 나뉘어 들어왔습니다. 서브 에이전트 셋을 띄워 담당을 하나씩 맡기는 법을 익힙니다. 그중 다섯 건(문의 5 · 7 · 8 · 12 · 13)은 다른 담당 파일에 적힌 사정(예: 형이 12월에 휴원한다)을 알아야 맞게 답할 수 있어서, 맡길 때 무엇을 같이 넘기느냐에 따라 답이 달라지는 것도 봅니다. 새 에이전트 파일은 만들지 않습니다.

방법
  1. ① 서브 셋 띄우기 — 그대로 나누기 — 상담원 셋에게 문의함을 하나씩 나눠 준 것과 같습니다. 서브끼리는 말할 수 없고, 메인은 붙이기만 합니다.
    담당별 폴더의 학부모 문의를 서브 에이전트 3개에게 나눠 맡겨 줘. - 서브 3개를 동시에 띄워 담당 A · B · C 를 하나씩 맡긴다. 각 서브는 담당별 폴더의 응대규정.md · 결론낱말.txt 와 자기 담당 파일 하나만 읽고(다른 담당 파일은 읽지 않는다) 담당별/답변/서브_A.md · 서브_B.md · 서브_C.md 로 저장한다 - 너(메인)는 문의 파일을 읽지 않는다. 세 파일을 문의 순서대로 이어 붙여 담당별/답변/서브.md 로 저장만 한다 (내용은 고치지 않는다) - 마지막에 문의 5 · 7 · 8 · 12 · 13 의 결론만 한 줄씩 보여 줘

    도는 동안 입력창 아래 패널에 서브가 셋 뜹니다. 메인에게 돌아오는 것은 서브가 쓴 마지막 요약뿐입니다.

  2. ② 챙겨서 넘기기 — 나누는 쪽(메인)이 얽힌 사정을 먼저 정리해 같이 넘겨 줍니다.
    이번에는 나누기 전에 메인이 준비를 해 줘. - 너(메인)가 먼저 문의_A · B · C 를 훑어 「같은 학부모 목록」(학부모 이름 → 문의 번호 · 내용 한 줄)을 만든다 - 서브 3개를 동시에 띄워 담당 A · B · C 를 나눠 주면서 이 목록을 같이 넘긴다. 각 서브는 자기 담당 파일 · 이 목록 · 응대규정.md · 결론낱말.txt 만 본다 - 결과는 담당별/답변/서브2_A.md · 서브2_B.md · 서브2_C.md 로 저장하고, 너는 이어 붙여 담당별/답변/서브2.md 로 저장만 한다 (내용은 고치지 않는다) - 마지막에 문의 5 · 7 · 8 · 12 · 13 의 결론을 서브 · 서브2 두 줄 표로 보여 줘
확인

패널에 서브가 셋 떴다가 끝났다. 담당별\답변\ 에 서브.md · 서브2.md 가 있다. 표에서 ① 과 ② 의 결론을 나란히 봤다 — 문의 5 처럼 다른 담당의 사정이 얽힌 문의는 ② 에서 결론이 바뀌기 쉽습니다(같아도 괜찮습니다). 워크스페이스의 .claude\agents\ 의 파일은 여전히 1개다.

서브에게 맡기는 요령서브는 맡길 때 받은 것만 압니다. 내 대화도, 다른 서브가 본 것도 모릅니다. 그래서 ① 에서는 「형이 휴원 중」이라는 사정을 알 길이 없었고, ② 처럼 필요한 정보는 맡기는 쪽이 챙겨 넘겨야 합니다. 미리 챙길 수 없을 때 서로 직접 묻게 하는 방법이 4단계 에이전트 팀입니다.
결과는 매번 같지 않습니다① 에서 서브가 몇 건을 우연히 맞힐 수도 있습니다. 그래도 「서로 모르는 채로 나눴다」는 구조는 같습니다.

PART 3팀과 판단 (4~5단계)

4

에이전트 팀 — 켜기 · 지켜보기 · 끄기

에이전트 팀은 팀원끼리 쪽지를 주고받습니다. 3단계 ① 과 똑같이 담당마다 자기 문의함만 보게 하고 메인은 붙이기만 하되, 이번에는 얽힐 것 같으면 그 담당에게 직접 묻게 합니다. 팀을 켜고 · 띄우고 · 쪽지를 지켜보고 · 팀원에게 직접 말을 걸고 · 끄는 순서를 익힙니다.

실험 기능에이전트 팀 기능은 기본으로 꺼져 있고(공식 문서 기준 실험 단계) 버전에 따라 화면이 바뀔 수 있습니다. 이 폴더에서만 켜고, 이 단계 끝에서 끕니다. 팀은 지금처럼 대화하며 쓰는 Claude 에서만 뜹니다 — 자동 실행(claude -p)에서는 이름을 붙여도 서브로 돕니다.
방법
  1. 에이전트 팀 기능 켜기 — 붙여넣은 뒤 exit → claude. (손으로 하려면 받은 팀켜기.txt)
    이 프로젝트의 .claude/settings.local.json 의 env 에 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS 를 "1" 로 넣어 줘. 파일이 없으면 만들고, 다른 설정은 건드리지 마. 전역 설정 파일은 고치지 마.
  2. 팀 회의
    에이전트 팀을 만들어 줘. 팀원 3명을 이름을 붙여(A · B · C) 동시에 띄우고, 팀원끼리는 SendMessage 로 직접 말하게 해. - 각 팀원은 담당별 폴더의 응대규정.md · 결론낱말.txt 와 자기 담당 파일(A = 문의_A.txt · B = 문의_B.txt · C = 문의_C.txt) 하나만 읽고 담당별/답변/팀_A.md · 팀_B.md · 팀_C.md 로 저장한다 - 같은 학부모 · 같은 아이처럼 다른 담당과 얽힐 것 같은 문의가 있으면 그 담당에게 SendMessage 로 직접 묻고 받은 답을 반영한다. 물어 오면 자기 파일을 보고 답해 준다 - 팀원끼리 메시지를 보낼 때마다 나에게도 「[참관] 보낸 이름 → 받는 이름 : 한 줄 요약」 사본을 보낸다. 나는 받은 줄을 그대로 보여 주기만 하고 옮기지 않는다 - 세 명이 끝나면 너는 세 파일을 문의 순서대로 이어 붙여 담당별/답변/팀.md 로 저장만 한다 (내용은 고치지 않는다) 팀원들은 이 대화를 모르니 각자에게 폴더 위치 · 할 일 · 다른 두 팀원의 이름과 담당을 분명히 알려 줘. 마지막에 문의 5 · 7 · 8 · 12 · 13 의 결론을 서브 · 서브2 · 팀 세 줄 표로 보여 줘(답변 폴더에 있는 파일만).

    팀원이 뜨면 [참관] 줄이 차례로 찍힙니다.

  3. 팀원에게 직접 말 걸기 — 입력창 아래 패널에서 ↑ ↓ 로 팀원 하나를 고르고 Enter. 그 팀원의 대화가 열리면 아래를 입력합니다. 나올 땐 Esc.
    지금 누구에게 무엇을 물어봤고 어떤 답을 받았는지 두 줄로 알려 줘.

    메인을 거치지 않고 팀원 하나와 직접 이야기하는 것이 서브와 다른 점입니다.

  4. 에이전트 팀 기능 끄기 — 붙여넣은 뒤 exit → claude.
    .claude/settings.local.json 에서 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS 줄을 지워 줘. 다른 설정은 건드리지 마.

3 · 4단계에서 서브와 팀을 쓰는 법을 익혔습니다. 이제 언제 쓸지를 정합니다. 결론부터: 대부분의 일은 싱글이 가장 싸고 빠르고, 결과도 같거나 낫습니다. 서브와 팀은 이유가 있을 때만 꺼냅니다.
