시작 전혼자 하던 일을 여러 AI 에게 나눠 봅니다

basic 1step에서 만든 직영 리포트 담당은 혼자 세고, 혼자 만들고, 혼자 검사했습니다. 사람 일도 혼자 다 하면 실수를 스스로 못 찾습니다. 오늘은 같은 리포트를 ① 담당 하나 ② 작성 담당 + 검산 담당(서브 에이전트) ③ 분석 · 제작 · 검토 세 명(에이전트 팀)으로 돌려 보고, 일하는 모양이 어떻게 다른지 봅니다.

끝나면 이렇게 됩니다
  • 리포트 담당 에이전트 파일에 업무 지시서(무엇을 · 어디에 저장 · 무엇을 보고 · 막히면)를 넣어 정식 담당으로 만들었다.
  • 검산 담당을 따로 불러, 일부러 틀린 숫자를 검산 담당이 잡아내는 것을 봤다.
  • 에이전트 팀에서 검토 담당이 분석 담당에게 직접 되돌려 보내는 회의 장면을 봤다. 끝나고 기능을 껐다.
  • 내 업무 하나를 판단표 네 칸(스킬 / 에이전트 / 서브 / 팀) 중 어디에 둘지 이유와 함께 말할 수 있다.

일을 나누는 세 가지 — 회사에서 일을 나누는 방식과 같습니다

회사라면Claude Code 에서는장점단점단계
담당자 한 명에게 통째로 맡김에이전트 하나만들기 쉽고 사용량이 적다. 결론만 받는다혼자 쓰고 혼자 확인해서 실수를 스스로 못 거른다2
작성자와 검토자를 나눔서브 에이전트 (작성 담당 + 검산 담당)쓰는 쪽 ≠ 확인하는 쪽이라 실수를 잡는다. 메인이 결과를 모아 보여 줘서 중간에 판단하기 쉽다담당끼리 직접 말하지 못하고 메인을 거쳐 전한다. 에이전트 하나보다 사용량이 많다3
회의 — 담당끼리 직접 말하며 고침에이전트 팀 (분석 · 제작 · 검토)팀원끼리 직접 여러 번 주고받으며 고친다. 갈래가 여럿인 큰 일에 강하다사용량이 가장 많다. 실험 기능이라 결과가 매번 다를 수 있고, 사람이 지켜봐야 한다4
사용량오늘은 넉넉히 써도 됩니다. 특히 에이전트 팀은 팀원마다 따로 일해서 사용량이 가장 많이 듭니다. 왜 그런지 · 언제 써야 하는지는 5단계에서 정리합니다.

PART 1보기와 준비 (1~2단계)

1

강사 시연 — 나눠서 일하는 장면 보기

방법

강사가 완성된 서브 에이전트와 에이전트 팀을 차례로 돌립니다. 두 가지만 봅니다.

  • 누가 누구에게 말하나 — 서브는 검산 결과를 메인 Claude 가 받아 옮깁니다. 팀은 [참관] reviewer → analyst 처럼 팀원끼리 직접 말합니다.
  • 틀린 숫자가 어떻게 고쳐지나 — 처음 숫자와 마지막 숫자가 다릅니다. 누가 찾았고 누가 고쳤는지 봅니다.
확인

[참관] 줄이 무엇인지(팀원끼리 주고받은 메시지의 사본) 말할 수 있다.

2

리포트 담당을 정식 에이전트로

여러 명에게 나누려면 먼저 한 명이 무엇을 맡는지가 분명해야 합니다. basic 1step의 리포트 담당 파일에 업무 지시서 네 칸을 넣어, 누가 불러도 같은 방식으로 일하는 정식 담당으로 만듭니다.

방법
  1. VS Code(또는 Cursor)에서 [파일] → [폴더 열기] → basic 1step의 basic_data.
  2. 윈도우 탐색기에서 워크스페이스 폴더(basic_data 바로 위 폴더 · 이름은 사람마다 다르다)의 .claude\agents\jig-report.md 와 .claude\skills\jig-metrics\SKILL.md 가 있는지 봅니다. VS Code 왼쪽 탐색기는 basic_data 만 보여 줘서 안 나옵니다.
  3. 터미널에서 claude 를 켜고 붙여넣습니다.
    basic_data 바로 위 폴더의 .claude/agents/jig-report.md 에 「## 업무 지시서」 칸을 넣어 줘. 다른 내용은 그대로 둬. - 무엇을: basic_data 의 직영_실습데이터.csv 로 가장 최근 편성년월의 과목수 · 학생수 리포트를 만든다 (세는 법 = jig-metrics 스킬) - 어디에 저장: basic_data/리포트/담당_오늘날짜(YYYYMMDD).html. 같은 이름이 있으면 _v2, _v3 를 붙인다 (덮어쓰지 않는다) - 무엇을 보고: 마지막 답은 결론 3줄 + 파일 이름만 - 막히면: 추측해서 채우지 말고 「확인 필요: 이유」 한 줄로 끝낸다 저장한 뒤 바뀐 부분만 보여 줘.

    파일 수정 허락 창이 뜨면 허용합니다.

  4. exit → claude 로 다시 켠 뒤(바뀐 에이전트 파일은 다시 켜야 읽힌다) 일을 시킵니다.
    jig-report 에이전트를 불러서 업무 지시서대로 리포트를 만들게 해 줘.
확인

에이전트 파일에 업무 지시서 네 줄이 있다. 답이 결론 3줄 + 파일 이름뿐이고, 리포트의 202609 과목수 · 학생수가 정답표 [1] 과 같다.

없으면받은 정답_리포트담당.md 를 워크스페이스의 .claude\agents\jig-report.md 로, 정답_jig-metrics 폴더를 워크스페이스의 .claude\skills\jig-metrics 로(폴더가 없으면 만든다) 넣은 뒤 exit → claude. 정답 파일에는 업무 지시서 칸이 이미 들어 있어 3번은 건너뜁니다.
② 나누기 3단계 · 15분

PART 2나누기 (3단계)

3

서브 에이전트 — 작성 ≠ 검산

자기가 쓴 것을 자기가 검사하면 통과시키는 쪽으로 기웁니다. 사람 일도 작성자와 검토자를 나눕니다. 새 에이전트 파일은 만들지 않습니다 — 이미 있는 일꾼을 검산 역할로 따로 한 번 더 부르는 것이 서브 에이전트입니다. 검산 담당이 정말 잡아내는지 보려고 일부러 틀리게 시킵니다.

방법
jig-report 에이전트로 202609 리포트를 만든 뒤, 에이전트를 하나 더 검산 담당으로 따로 불러 줘. - 이번에는 시험이라 jig-report 에게 제외 프로그램 목록(셔틀 · 차량 등)을 빼지 말고 세라고 한다. 세는 단위와 휴회 · 반이동 조건은 그대로 둔다 - 검산 담당은 리포트의 과목수 · 학생수를 jig-metrics 기준으로 CSV 에서 다시 세어 대조하고, 다른 숫자와 이유만 돌려준다 (리포트는 고치지 않는다) - 다르면 그 내용을 jig-report 에게 전해 고친 리포트를 다시 만들게 한다 - 검산 담당 에이전트 파일은 새로 만들지 않는다 - 마지막에 「처음 숫자 → 검산 결과 → 고친 숫자」 한 줄과 「검산: 일치」 또는 「검산: 고침 — 무엇」 한 줄을 보여 줘
확인

처음 숫자가 정답표 [5], 고친 숫자가 정답표 [1] 이고 「검산: 고침」 줄이 있다. 워크스페이스의 .claude\agents\ 의 파일은 여전히 1개다.

누가 전했나검산 담당은 리포트 담당에게 직접 말하지 못했습니다. 메인 Claude 가 결과를 받아 옮겼습니다. 이 「중간 전달」이 없는 것이 4단계 에이전트 팀입니다.

PART 3팀과 판단 (4~5단계)

4

에이전트 팀 — 기능 켜기 · 회의 · 끄기

에이전트 팀은 담당끼리 쪽지를 주고받으며 스스로 고칩니다. 3단계와 같은 오류를 일부러 넣고, 검토 담당이 분석 담당에게 직접 되돌려 보내는지 봅니다.

실험 기능에이전트 팀 기능은 기본으로 꺼져 있고 버전에 따라 화면이 바뀔 수 있습니다. 이 폴더에서만 켜고, 이 단계 끝에서 끕니다.
방법
  1. 에이전트 팀 기능 켜기 — 붙여넣은 뒤 exit → claude. (손으로 하려면 받은 팀켜기.txt)
    이 프로젝트의 .claude/settings.local.json 의 env 에 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS 를 "1" 로 넣어 줘. 파일이 없으면 만들고, 다른 설정은 건드리지 마. 전역 설정 파일은 고치지 마.
  2. 팀 회의
    에이전트 팀을 만들어 줘. 팀원 3명을 이름을 붙여(analyst · builder · reviewer) 동시에 띄우고, 팀원끼리는 SendMessage 로 직접 말하게 해. - analyst 분석 담당 (직영 리포트 담당 타입): 202609 과목수 · 학생수를 센다. 처음에는 jig-metrics 스킬을 쓰지 말고, 제외 프로그램 목록(셔틀 · 차량 등)만 빼지 말고 센다. 세는 단위와 휴회 · 반이동 조건은 그대로 둔다. 다 세면 숫자를 builder 와 reviewer 에게 보낸다. reviewer 가 고치라고 하면 그 말대로 다시 세서 둘에게 다시 보낸다 - builder 제작 담당 (직영 리포트 담당 타입): analyst 에게 받은 숫자로 리포트/팀.html 을 만든다. 숫자가 바뀌면 다시 만들고 reviewer 에게 알린다 - reviewer 검토 담당: jig-metrics 기준으로 CSV 에서 다시 세어 analyst 의 숫자와 대조하고, 다르면 analyst 에게 직접 SendMessage 로 무엇이 왜 다른지 되돌려 보낸다. 고쳐진 리포트가 나오면 나에게 최종 결과를 준다 - 팀원끼리 메시지를 보낼 때마다 나에게도 「[참관] 보낸 이름 → 받는 이름 : 한 줄 요약」 사본을 보낸다. 나는 받은 줄을 그대로 보여 주기만 하고 옮기지 않는다 팀원들은 이 대화를 모르니, 각자에게 이 폴더 위치 · 파일 위치 · 할 일 · 다른 두 팀원의 이름과 할 일을 분명히 알려 줘. 나는 중간에 전달하지 않는다.

    팀원이 뜨면 [참관] 줄이 차례로 찍힙니다. 더 보려면 ↑ ↓ 로 팀원을 고르고 Enter, 나올 땐 Esc.

  3. 에이전트 팀 기능 끄기 — 붙여넣은 뒤 exit → claude.
    .claude/settings.local.json 에서 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS 줄을 지워 줘. 다른 설정은 건드리지 마.
확인

[참관] reviewer → analyst 줄이 보였다(에이전트가 여럿 떴다는 것만으로는 팀인지 서브인지 모릅니다). 리포트\팀.html 의 숫자가 정답표 [1] 과 같다. settings.local.json 에 그 줄이 없다.

팀 대신 서브가 떴다면패널에 analyst · builder · reviewer 이름 없이 에이전트만 뜨고 [참관] 줄이 안 나오면 서브입니다. 에이전트 팀 기능을 켠 뒤 exit → claude 를 안 했을 때 그렇습니다.
꼭 끕니다켜 둔 채로 두면 평소에 부탁한 일도 팀원으로 나뉘어 돌 수 있고 사용량이 빨리 닳습니다.
5

판단표 네 칸 + 팀 비용

무엇에게 맡길까

칸이럴 때 고른다오늘 본 것사용량
스킬세는 법 · 기준처럼 지금 대화에 매뉴얼만 얹으면 되는 일jig-metrics가장 적다
에이전트한 담당에게 통째로 맡기고 결론만 받는 일2단계 리포트 담당적다
서브 에이전트작성과 검산처럼 나눠야 하지만, 중간 전달은 메인이 해도 되는 일3단계 검산 담당중간
에이전트 팀담당끼리 의견을 주고받아야 좋아지는 일. 사람이 지켜볼 수 있을 때만4단계 회의가장 많다
서브 vs 팀 — 고르는 기준 여섯 가지
물어볼 것그렇다면
담당끼리 여러 번 주고받아야 하나?팀 (한 번 검산하고 끝이면 서브)
중간 결과를 내가 보고 판단해야 하나?서브 (메인이 모아서 보여 준다)
사용량을 아껴야 하나?서브
실험 기능이라 바뀌어도 괜찮나?괜찮으면 팀, 매번 같아야 하면 서브
일이 크고 갈래가 여럿인가?팀
내가 끝까지 지켜볼 수 있나?못 보면 서브
팀이 사용량을 많이 쓰는 이유 · 줄이는 법팀원마다 따로 Claude 가 하나씩 떠서 파일을 각자 읽고, 메시지를 주고받을 때마다 또 읽습니다. 줄이려면 ① 팀원은 꼭 필요한 수만 ② 팀원에게 필요한 파일 · 할 일만 알려 주기 ③ 끝나면 에이전트 팀 기능 끄기 ④ 서브로 되는 일은 서브로.

어떤 업무를 맡기면 좋을까

구분가장 잘 맞는 업무업무 예시맞지 않는 업무
싱글 에이전트기준이 정해져 있고 한 번에 끝나는 일월별 과목수 · 학생수 집계 리포트 · 회의록 요약 · 정해진 양식의 보고서 초안숫자가 틀리면 안 되는데 따로 확인할 사람이 없는 일
서브 에이전트만든 것을 다른 눈으로 확인해야 하거나, 서로 상관없는 조사를 나눠 동시에 하는 일매출 리포트 작성 + 검산 · 공지문 작성 + 사실 확인 · 센터별 자료를 나눠 조사해 한데 모으기담당끼리 의견을 여러 번 주고받아야 결론이 나는 일
에이전트 팀관점이 다른 담당이 서로 반박하며 좋아지는 크고 갈래 많은 일새 이벤트 기획(분석 · 기획 · 검토가 토론) · 대시보드 화면 설계(데이터 · 디자인 · 사용자 관점) · 지표가 떨어진 원인을 가설끼리 반박해 좁히기정해진 순서대로 하면 끝나는 일 · 사람이 지켜볼 수 없는 일 · 사용량을 아껴야 하는 일
