시작 전교육 편에서 만든 것을 그대로 씁니다

교육 편의 basic_data 폴더 · jig-metrics 스킬 · 직영 리포트 담당 에이전트를 가져옵니다. 교육 편에서 한 명에게 맡겼던 같은 리포트를 이번에는 여럿에게 나눠 맡기고(서브), 마지막엔 서로 말을 주고받는 팀으로 만들어 봅니다. 일이 같으니 달라지는 건 일하는 방식뿐입니다.

끝나면 이렇게 됩니다
  • 에이전트 파일은 하나인데 셋이 동시에 도는 것을 봤다 — 서브는 새 종류가 아니라 「여러 번 부르는 것」이다.
  • 관점별로 나눠 맡긴 결과를 리포트 하나로 합치고, 한 명에게 맡긴 것과 비교표를 내 손으로 채웠다.
  • 검산 담당이 찾은 틀린 곳을 내가 전달해서 다시 시켰고, 팀에서는 같은 오류를 팀원끼리 직접 고치는 것을 봤다.
  • 관찰표 세 칸(싱글 · 서브 · 팀)을 내 숫자로 채우고 네 칸 판단표를 완성했다.

관찰표 — 세 번 모두 같은 칸을 채웁니다

교육 편 12단계에서 채운 관찰표.txt 를 메모장으로 열어 둡니다. 「싱글」 칸은 이미 있고, 오늘 「서브」(5단계) · 「팀」(7단계) 칸을 채웁니다. 시간 · 토큰은 에이전트가 끝날 때 화면에 뜨는 값을 옮겨 적습니다. 정확한 값이 아니라 대략 몇 배인지만 봅니다.

아래 표는 예상 값입니다. 내 관찰표에 실제로 본 값을 적고, 이 표와 무엇이 같고 다른지 봅니다.

PART 1강사 시연 · 준비 (1~2단계)

1

생각 열기 — 강사 시연 보기

방법

강사가 완성된 서브 에이전트와 에이전트 팀이 직영 데이터를 분석하는 화면을 보여 줍니다. 세 가지만 봅니다.

  • 에이전트 패널에 몇 명이 뜨는가.
  • 서브: 결과가 부른 쪽(메인)에게만 모인다.
  • 팀: 팀원끼리 쪽지를 주고받는다. 검토 담당이 분석 담당에게 직접 되돌려 보낸다 — 강사 화면에 [참관] reviewer → analyst : … 줄로 찍힌다.
확인

「서브와 팀은 결과가 누구에게 가느냐가 다르다」를 말할 수 있다.

2

교육 편 폴더 열고 스킬 · 에이전트 확인

방법
  1. VS Code(또는 Cursor)에서 [파일] → [폴더 열기] → 교육 편의 basic_data.
  2. 탐색기에서 .claude/agents/jig-report.md 와 .claude/skills/jig-metrics/SKILL.md 가 있는지 봅니다.
  3. 터미널에서 claude → 「이 프로젝트에서 쓸 수 있는 에이전트 목록 보여 줘」로 직영 리포트 담당, /skills 로 jig-metrics 를 봅니다.
  4. 관찰표.txt 를 메모장으로 엽니다.
확인

에이전트 · 스킬이 목록에 보이고, 관찰표에 싱글 칸이 채워져 있다.

없으면받은 정답_리포트담당.md 를 basic_data\.claude\agents\jig-report.md 로, 정답_jig-metrics 폴더를 basic_data\.claude\skills\jig-metrics 로 넣은 뒤 exit → claude. 관찰표 싱글 칸이 비어 있으면 교육 편 12단계 카드를 한 번 돌려 채웁니다.
② 서브 에이전트 3~5단계 · 30분

PART 2서브 에이전트 — 나눠 맡기기 (3~5단계)

싱글과 서브는 같은 에이전트 파일입니다. 다른 것은 누가, 몇 번 부르느냐뿐입니다. 사실 .claude/agents 의 파일은 Claude Code 공식 문서에서 서브 에이전트(subagent)라고 부릅니다 — 지금 대화하는 Claude(메인)가 일을 넘겨 맡기는 쪽이라 「서브」입니다. 교육 편에서는 한 명에게만 맡겨서 그냥 「에이전트」라고 불렀습니다. 받은 초급_실습표.txt 를 메모장으로 열어 둡니다.

3

파일 하나로 셋이 동시에 — 센터 3곳 리포트

방법
직영 리포트 담당 에이전트 3개를 동시에 불러 줘. 202609 기준으로 행이 가장 많은 센터 3곳을 골라 한 곳씩 맡기고, 각자 리포트/센터_1.html · 센터_2.html · 센터_3.html 로 저장해. 에이전트 파일은 새로 만들지 마. 센터를 고를 때도 Node 명령으로 세어 줘(Python 은 쓰지 마).

도는 동안 에이전트 패널에서 ↑ ↓ · Enter 로 한 명씩 열어 봅니다.

확인

.claude\agents\ 의 파일은 여전히 1개인데, 패널에는 3명이 떴다. 리포트 폴더에 센터 파일 3개가 생겼다.

무엇을 본 건가요교육 편에서 내가 부르던 담당을, 이번엔 메인 Claude 가 세 번 불렀습니다. 서브는 새로운 종류의 에이전트가 아니라 부르는 관계입니다. 그래서 파일을 열어 봐서는 싱글인지 서브인지 모릅니다.
4

관점별로 나눠 합치기 — 한 명 vs 셋 비교표

방법
  1. A 한 명에게 통째로 — 시작 시각을 적고 붙여넣습니다.
    직영 리포트 담당 하나에게 세 가지를 모두 맡겨 줘. ① 월별 과목수 추이 ② 월별 학생수와 신규생 · 재입회생 수(신규재원 열) ③ 202609 학년별 학생수. 리포트/관점_한명.html 로 저장해.
  2. B 셋으로 나눠 동시에 — /clear 후 시작 시각을 적고 붙여넣습니다.
    같은 세 가지(① 월별 과목수 추이 ② 월별 학생수와 신규생 · 재입회생 수 ③ 202609 학년별 학생수)를 직영 리포트 담당 3개에게 하나씩 동시에 맡기고, 셋의 결과를 리포트/관점_셋.html 하나로 합쳐 줘. 합칠 때도 Node 명령으로 해 줘(Python 은 쓰지 마).
  3. 실습표의 A · B 비교표를 내 손으로 채웁니다. 아래는 예상 값입니다 — 내가 본 것과 비교합니다.
비교 항목하나에게 (A)셋으로 나눠 (B)
걸린 시간세 가지를 차례로 해서 가장 길다동시에 돌아 짧다 (합치는 시간은 더해진다)
내가 읽은 양리포트 1개 · 결론 3줄세 명의 요약 + 합친 리포트 1개 (조금 많다)
중간에 내가 끼어들 수 있었나못한다못한다 (셋 다 따로 돈다)
결론을 그대로 쓸 수 있었나한 사람이 써서 표 모양 · 말투가 고르다합친 리포트의 표 모양 · 기준이 제각각일 수 있어 한 번 확인이 필요하다
확인

B 에서 에이전트 3개가 동시에 도는 표시가 뜨고, 합친 리포트가 생겼다. 비교표 4줄을 채웠다.

나누는 게 늘 이득은 아닙니다세 관점은 서로 독립이라 나눠도 됩니다. 앞 결과를 보고 다음 일을 해야 하는 일은 나누면 오히려 틀립니다.
5

검산 담당 따로 두고 다시 시키기 · 관찰표 서브 칸

에이전트에게 맡긴 일은 나도, 부른 쪽 Claude 도 과정을 못 봤습니다. 그래서 「확인했습니다」라는 말이 아니라 결과물과 근거를 보고 판단합니다.

무엇을 보고 판단하나이대로면
에이전트의 말 「다 셌습니다」자기가 자기를 채점한 것. 믿지 않는다
결과물과 근거(어떻게 셌나)사람이 하던 검토와 같다. 여기까지 한다
방법
  1. 일부러 틀린 리포트 만들기 — 제외 프로그램 목록만 빼먹고 세게 합니다.
    직영 리포트 담당에게 202609 과목수 · 학생수 리포트를 만들게 해 줘. 이번에는 jig-metrics 스킬을 쓰지 말고, 제외 프로그램 목록(셔틀 · 차량 등)만 빼지 말고 세라고 해. 세는 단위와 휴회 · 반이동 조건은 그대로 둔다. 리포트/검산전.html 로 저장. 나중에 고치라는 말을 받으면 그 말대로 다시 센다.
  2. 검산 담당을 따로 부릅니다.
    에이전트 하나를 검산 담당으로 따로 불러 줘. 리포트/검산전.html 의 숫자를 jig-metrics 기준으로 CSV 에서 다시 세어 대조하고, 다른 숫자와 그 이유만 목록으로 나에게 돌려준다. 리포트는 고치지 않는다.
  3. 내가 전달합니다. 검산 결과를 보고 붙여넣습니다.
    방금 검산 결과를 직영 리포트 담당에게 전해서, 고친 리포트를 리포트/검산후.html 로 다시 만들게 해 줘. 무엇을 고쳤는지 근거도 같이 받아 줘.
  4. 관찰표 「서브」 칸을 채웁니다. 「내가 중간에서 전달한 횟수」에 3번 카드까지 몇 번 옮겼는지 적습니다.
확인

검산후.html 의 숫자가 검산전.html 과 달라졌고 정답표 [1] 과 같다(검산전은 정답표 [5] 의 오류값). 실습표 「다시 시키기 전 / 후」 칸을 채웠다.

왜 나누나요자기가 쓴 것을 자기가 검사하면 통과시키는 쪽으로 기웁니다. 사람 일도 작성자와 검토자를 나눕니다. 그리고 서브끼리는 서로 모릅니다 — 검산 담당이 찾은 것을 리포트 담당에게 옮긴 건 나였습니다.
먼저 끝났다면 — 심화: 학생수를 전체에서 한 번에 세면?

회사 기준 학생수는 센터별로 센 뒤 더한 값입니다. 두 센터를 다니는 학생은 센터마다 한 명씩 셉니다. 전체에서 한 번에 세면 그만큼 작아집니다(정답표 [4]). 기준을 모르는 담당이 어느 쪽으로 세는지 숫자로 확인해 봅니다.

방법

마무리 — 토큰이 충분하면 팀이 늘 더 좋을까?

아이디어를 질문을 한 번에 하나씩 받아 가며 요구사항과 설계로 다듬는 스킬입니다. 작은 일은 채팅으로, 큰 일은 설계 문서로 내가 승인한 뒤에만 만들기 시작합니다. 교육 편에서는 스킬을 직접 만들었고, 이번엔 남이 만든 스킬을 골라 고쳐 쓴 예를 봅니다.

방법
  1. 받은 skills\brainstorming 폴더를 .claude\skills\ 안에 넣습니다. 모든 폴더에서 쓰려면 전역 C:\Users\<내 계정>\.claude\skills\ 에 넣습니다. 넣을지는 각자 고릅니다.

왜 이것 하나만 주나요이 스킬은 superpowers 라는 플러그인에 들어 있습니다. 플러그인 전체를 깔면 매 세션 시작마다 「조금이라도 해당하면 스킬부터 쓰라」는 규칙을 끼워 넣어서, 입문에서 받은 token-efficient(간결하게) 스킬과 정반대로 부딪히고 개발용 스킬도 헛돕니다. 필요한 것 하나만 골라 받아 고쳐 쓰는 것이 요령입니다.

3헛걸음이 줄어든다Claude 가 데이터를 셀 때 먼저 고르는 도구가 Python 입니다. 없으면 시도 → 실패 → 다른 도구로 바꾸기를 거치느라 시간과 사용량을 더 씁니다
4한글 인코딩 · 큰 파일에 강하다회사 파일에 흔한 EUC-KR(cp949) 변환, 수십만 행 집계를 Python 은 쉽게 처리합니다. PowerShell 은 이 두 군데서 틀리거나 느려지기 쉽습니다
5그래프 · PDF 를 파일로 만든다차트 그림 · PDF 보고서를 파일로 뽑을 수 있습니다. 오늘 리포트는 HTML 안에서 그래프를 그려서 필요 없었습니다
6만든 스크립트를 다시 쓴다Claude 가 짠 집계 스크립트를 저장해 두고 매달 다시 돌리는 일이 자동화의 출발점입니다
방법
  1. python.org Windows 다운로드 에서 최신 안정판의 Windows installer (64-bit) 를 받습니다.
  2. 설치 파일을 열고 첫 화면 맨 아래 「Add python.exe to PATH」를 체크한 뒤 Install Now. 내 계정에만 깔리는 방식이라 관리자 권한이 없어도 됩니다.
  3. VS Code 를 껐다 켜고(새 터미널이라야 Python 을 찾습니다) claude → 붙여넣습니다.
    python --version 이 되는지 확인해 줘. 안 되면 무엇이 문제인지만 알려 주고, 아무것도 설치하지는 마.
확인

Python 3. 으로 시작하는 버전 번호가 나온다.

주의윈도우에서는 python3 이 진짜 Python 이 아니라 Microsoft Store 바로가기로 연결됩니다. Claude 가 python3 을 쓰다 막히거나 스토어 창이 뜨면 「python3 말고 python 으로 해」라고 말합니다.

PART 5막혔을 때

먼저직영 리포트 담당이나 jig-metrics 가 없거나 이상하면 받은 정답 파일(2단계 「없으면」)로 넣고 다시 켭니다. 나머지 단계는 모두 이 파일로 됩니다.
증상원인해결
에이전트 목록에 리포트 담당이 없다다른 폴더를 열었다 · .claude/agents/ 에 파일이 없다basic_data 를 열었는지 확인 · 정답 파일
3단계에서 에이전트 파일이 새로 생겼다「새로 만들지 마」가 빠졌다새 파일은 지우고 카드를 그대로 다시 붙여넣는다
나눠 달랬는데 에이전트가 하나만 돈다나눠 달라는 말이 약했다「3개에게 하나씩 동시에」를 그대로 붙여넣는다
5단계 검산전 리포트가 처음부터 맞게 나왔다스킬이 저절로 불려왔다「jig-metrics 스킬을 쓰지 말고」를 문장 앞쪽에 둔다
다시 시켰는데 결과가 똑같다무엇이 틀렸는지 전하지 않았다검산 결과(다른 숫자 · 이유)를 문장에 넣는다
팀을 만들어 달랬는데 서브로 처리했다 · [참관] 줄이 안 나온다팀 기능이 안 켜졌다 · 켠 뒤 다시 켜지 않았다 (꺼져 있으면 이름 붙인 팀원을 못 띄운다)6단계 확인 → exit → claude → 7단계 카드 그대로
팀원 화면이 안 열린다키를 다르게 눌렀다↑ ↓ 로 고르고 Enter, 나올 땐 Esc
사용량 한도에 걸렸다여럿이 동시에 돌아 많이 쓴다강사 화면으로 보고 8단계 판단표 · 팀 끄기로 넘어간다
팀을 껐는데 평소 일이 여럿으로 나뉜다끈 뒤 다시 켜지 않았다exit → claude
설치했는데 python --version 이 안 된다 · 스토어 창이 뜬다설치 때 「Add python.exe to PATH」를 체크하지 않았다 · 터미널을 새로 열지 않았다VS Code 를 껐다 켠다. 그래도 안 되면 설치 파일을 다시 열어 Uninstall → 체크하고 다시 설치
Claude 가 python3 을 쓰다 막힌다윈도우의 python3 은 스토어 바로가기다「python3 말고 python 으로 해」
