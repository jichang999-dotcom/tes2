오늘 흐름 — 뒤쪽은 한 줄로 이어집니다

  1. Git · GitHub — 내 워크스페이스를 기록하고 비공개로 백업한다 · 내 업무에 맞는 스킬을 찾아 쓴다 (1~10단계)
  2. 검색 스크립트 — 9단계 검색을 매일 도는 스크립트로 · 결과는 구글 드라이브 내 작업 폴더에 (11단계)
  3. 작업 스케줄러 — 그 스크립트를 매일 아침 저절로 (12~13단계)
  4. 슬랙 웹훅 — 내 슬랙에 가입하고, 끝나면 「새 저장소 N건」을 슬랙으로 (14~16단계)

PART 2내 워크스페이스를 Git 으로

Git 을 켜도 아무것도 올라가지 않습니다Git 은 내 PC 안에서만 기록합니다. 인터넷에 올라가는 것은 8단계 push 때뿐이고, 그때도 제외 목록에 없는 파일만 올라갑니다.
1

워크스페이스에서 Git 시작

방법
  1. VS Code 에서 평소 쓰는 워크스페이스를 열고 터미널에서 claude.
  2. [복사] → 붙여넣기 → Enter.
    지금 워크스페이스를 Git 으로 관리하고 싶어. 아래 순서로 하되, 저장(커밋)은 내가 확인한 뒤에만 해 줘. 1. 지금 폴더의 전체 경로와 바로 아래 폴더 목록을 보여 줘. 이 폴더 바깥은 건드리지 마. 2. git --version 으로 Git 이 있는지 확인해. 없으면 멈추지 말고 네가 설치해: winget install --id Git.Git -e --source winget --accept-package-agreements --accept-source-agreements. winget 이 없거나 실패하면 git-for-windows 의 GitHub 최신 릴리스에서 64-bit.exe 설치 파일을 받아 /VERYSILENT /NORESTART 로 설치해. 관리자 허락 창이 뜨면 내가 누를게. 설치 직후 git 을 못 찾으면 이 대화가 끝날 때까지 C:\Program Files\Git\cmd\git.exe 전체 경로로 실행해. 나에게 껐다 켜라고 하지 말고 끝까지 이어서 해. 3. 이미 Git 저장소면 새로 만들지 말고 git status 만 보여 주고 멈춰. 4. 제외 목록(.gitignore) 후보를 보여 줘. 기본은 .env, data/, *.csv, *.xlsx, *.xls 이고, 그 밖에 사람 이름 · 연락처 · 실적 데이터가 들어 있을 것 같은 폴더 · 파일도 후보로 골라 이유와 함께 보여 줘. 그런 파일의 내용은 화면에 옮기지 마. 「선택」 후보는 내가 정할 때까지 넣지 마. 5. 내가 「좋아」라고 하면 Git 저장소로 만들고(기본 브랜치 main), 제외 목록을 .gitignore 로 저장해 줘. 6. 기록될 파일 목록(git status)을 보여 줘. 데이터 · 개인정보로 보이는 파일이 있으면 멈추고 알려 줘. 7. 내가 다시 「좋아」라고 하면 「처음 저장」 메시지로 커밋해 줘. 이름 · 메일이 설정돼 있지 않으면 나에게 묻고 이 저장소에만(--local) 설정해 줘.
  3. 4번 후보 목록을 읽고, 빼야 할 폴더가 더 있으면 말로 더합니다 → 「좋아」.
  4. 6번 기록될 파일 목록에 데이터 · 개인정보가 없으면 → 다시 「좋아」.
  5. 이름 · 메일을 물으면 답합니다. 메일은 6단계에서 GitHub 에 가입할 메일(회사 메일)과 같게 — 다르면 올린 커밋이 내 계정과 이어지지 않습니다.
확인

터미널에서 git --version 을 쳐서 번호가 나오는지 한 번 확인합니다. Git 을 방금 설치했다면 VS Code 창을 모두 닫았다가 다시 연 뒤에 칩니다.

주의한 번 기록된 파일은 나중에 제외 목록에 넣어도 기록에 남습니다. 그래서 저장 전에 두 번(4 · 6번) 확인합니다. 의심되면 일단 제외 목록에 넣습니다 — 빼는 것은 언제든 됩니다.
주의VS Code 왼쪽 소스 제어에 파란 「게시 Branch」 버튼이 보여도 누르지 않습니다. GitHub 에 올리는 일은 7 · 8단계에서 비공개 리포로 합니다.
「LF will be replaced by CRLF」 경고가 나오면Windows 에서 줄바꿈 형식을 맞춘다는 안내입니다. 오류가 아니고 파일 내용은 그대로입니다.
커밋 메시지 아래에 Co-Authored-By: Claude 줄이 붙어 있으면Claude 와 같이 만든 커밋이라는 표시입니다. 정상입니다.
워크스페이스가 아주 크면첫 저장이 오래 걸립니다. 큰 데이터 폴더를 제외 목록에 넣거나, 워크스페이스 안의 프로젝트 폴더 하나만 Git 으로 시작해도 됩니다.

PART 3저장 · 되돌리기 · 브랜치

실제 업무 파일로 연습하지 않도록, 연습할 폴더를 내가 골라 그 안에서만 합니다.

2

연습 폴더 고르기

방법
  1. 저장 · 되돌리기 · 브랜치를 연습할 폴더를 고르려고 해. 이 워크스페이스의 하위 폴더 목록을 파일 수와 함께 보여 주고, 연습하기 좋은 폴더(실제 데이터 · 중요한 결과물이 없는 곳)를 추천해 줘. 아무것도 바꾸지 마.
  2. 하나를 고릅니다. 마땅한 곳이 없으면 탐색기에서 새 폴더(예: git_practice)를 만들고 빈 텍스트 파일 메모.txt 를 하나 넣습니다.
  3. Claude Code 에서 exit → VS Code 에서 [파일] → [폴더 열기] 로 고른 폴더를 열고 → claude. 1단계에서 Git 을 새로 설치했다면 그 전에 VS Code 창을 모두 닫았다가 다시 엽니다 — 그래야 새 터미널이 git 을 찾습니다.
확인

VS Code 왼쪽 위 폴더 이름이 고른 폴더다. 3~5단계는 이 창에서 합니다.

왜 그 폴더를 열고 켜나요Claude 는 켠 폴더를 기준으로 일합니다. 연습 폴더에서 켜면 그 바깥 파일을 건드릴 일이 줄고, 10단계에서 받은 스킬도 이 폴더에서 바로 보입니다. Git 기록은 1단계 저장소에 그대로 쌓입니다.
3

저장 · 비교

방법
이 폴더 안의 파일 하나를 골라(없으면 메모.txt 를 만들어) 맨 끝에 「Git 연습: 첫 수정」 한 줄을 추가해 줘. 이 폴더 바깥 파일은 건드리지 마. 저장 전에 git diff 로 바뀐 곳을 보여 주고, 이 폴더 안 파일만 git add 해서 「연습: 첫 수정」 메시지로 커밋해 줘. 마지막에 git log --oneline -3 을 보여 줘.
확인

diff 에 +Git 연습: 첫 수정 이 보이고, 커밋이 하나 늘었다.

커밋 = 저장 지점게임의 세이브 포인트처럼 커밋마다 그 순간의 파일 상태가 남습니다. 메시지는 「무엇을 왜」를 짧게 — 나중에 목록만 봐도 찾을 수 있게.
VS Code 왼쪽 「소스 제어」 화면 읽는 법
번호보이는 것뜻
①아이콘 위 숫자 (예: 1)아직 커밋하지 않은 파일 수
②변경 사항 목록마지막 커밋 뒤에 바뀐 파일. 오른쪽 글자 M = 고침 · U = 새 파일 · D = 지움
③파란 「커밋」 버튼누르지 않습니다 — 커밋은 카드대로 Claude 에게 시킵니다
④파일 옆 되돌리기 화살표누르면 그 파일의 고친 내용이 바로 사라집니다. 누르지 않습니다
⑤그래프커밋 목록. 위가 최신이고, main 표시가 지금 내가 있는 자리
내가 시키지 않은 파일이 변경 사항에 있으면 그 파일을 눌러 무엇이 바뀌었는지 본 뒤 Claude 에게 「이 파일은 왜 바뀌었어? 아직 아무것도 하지 마」라고 묻습니다. 3단계 프롬프트는 연습 폴더 안 파일만 커밋하므로, 바깥 파일이 남아 있는 것 자체는 정상입니다.
4

되돌리기

방법
3단계에서 고친 파일의 그 줄을 일부러 「Git 연습: 실수」로 바꿔 「연습: 실수」 메시지로 커밋해 줘. 그다음 방금 커밋을 되돌려 줘. 기록은 지우지 말고 되돌리는 커밋을 새로 만들어(git revert). 그 파일 내용과 git log --oneline -4 를 보여 줘.
확인

파일이 「첫 수정」으로 돌아왔고, 목록 맨 위에 Revert "연습: 실수" 가 있다.

주의「기록까지 지우는 되돌리기」(git reset --hard)는 시키지 않습니다. 지운 기록은 다시 못 찾습니다.
5

브랜치

방법
test 브랜치를 만들어 거기서 3단계 파일에 「브랜치에서 쓴 줄」을 추가하고 커밋해 줘(이 폴더 안 파일만). main 으로 돌아와서 그 파일에 그 줄이 없는 것을 보여 주고, git diff main test 로 두 브랜치의 차이를 보여 줘. 합치지는 마.
확인

git branch 에 main · test, 지금은 main 이고 파일에 그 줄이 없다.

브랜치는 언제 쓰나요잘 돌고 있는 스크립트를 크게 고쳐 볼 때. test 에서 고쳐 보고, 괜찮으면 main 에 합치고, 아니면 버립니다. main 은 그동안 멀쩡합니다.
주의브랜치를 바꾸기 전에는 저장 안 한 수정이 없어야 합니다. 「저장 안 한 변경이 있다」고 하면 먼저 커밋하거나 Claude 에게 「어떻게 할지 물어봐 줘」라고 합니다.
② GitHub 6~10단계 · 40분

PART 4GitHub — 가입 · 리포 · 올리기

6

가입

방법
  1. github.com/signup → 회사 메일 · 비밀번호 · 사용자 이름(영문)을 넣습니다. 이미 계정이 있으면 로그인만.
  2. 메일로 온 인증 코드를 넣습니다.
  3. 로그인 뒤 오른쪽 위 프로필 → Settings → Password and authentication → 2단계 인증을 켭니다(휴대폰 인증 앱).
확인

오른쪽 위에 내 프로필 사진(기본 그림)이 보이고, 2단계 인증이 켜져 있다.

7

비공개 리포 만들기

방법
  1. [복사] → 붙여넣기 → Enter.
    GitHub 에 비공개 리포를 만들고 싶어. GitHub CLI(gh)로 해 줘. 1. gh --version 으로 GitHub CLI 가 있는지 봐. 없으면 winget install --id GitHub.cli -e 로 설치해. 설치 창 · 관리자 허락 창이 뜨면 내가 누를게. 설치 직후 gh 를 못 찾으면 C:\Program Files\GitHub CLI\gh.exe 전체 경로로 실행해. 2. gh auth status 로 로그인돼 있는지 봐. 안 돼 있으면 멈추고, 내가 VS Code 새 터미널에서 칠 로그인 명령 한 줄만 알려 줘. 비밀번호나 토큰을 대화창에 묻지 마. 3. 로그인이 확인되면 gh auth setup-git 을 실행해(8단계 push 때 이 로그인을 쓰게). 4. 리포 이름은 지금 Git 저장소 최상위 폴더 이름(git rev-parse --show-toplevel)으로 하되, 한글 · 공백이 있으면 영문 소문자와 - 로 바꾼 이름을 제안하고 내 「좋아」를 기다려. 5. gh repo create <이름> --private 로 만들어 줘. README 는 넣지 마(이미 저장소가 있다). 아직 push 하지 마. 6. gh repo view <이름> --json name,visibility,url 로 비공개(PRIVATE)인지 보여 줘.
  2. 2번에서 멈추면: VS Code 터미널 오른쪽 위 + 로 새 터미널을 열어 Claude 가 알려 준 명령(gh auth login --web 모양)을 칩니다 → 화면의 8자리 코드를 복사 → Enter → 열린 브라우저에 코드 붙여넣기 → Authorize. 끝나면 Claude 창으로 돌아와 「로그인했어」.
확인

Claude 가 보여 준 결과에 "visibility":"PRIVATE" 가 있고, github.com 내 프로필 → Repositories 에서 리포 이름 옆에 Private 표시가 보인다.

gh 가 뭔가요GitHub 웹사이트에서 버튼으로 하던 일(리포 만들기 · 설정 보기)을 명령으로 하는 GitHub 공식 프로그램입니다. 그래서 Claude 에게 말로 시킬 수 있습니다. 로그인만은 사람이 브라우저에서 합니다.
주의Public 으로 만들지 않습니다. 공개 리포는 검색으로 누구나 봅니다. 실수로 키 · 개인정보가 올라가면 지워도 복사본을 회수할 수 없습니다.
8

올리기 (push)

방법
GitHub 에 올리기 전에 확인부터 해 줘. 1. 올라갈 파일 목록(git ls-files)을 보여 줘. .env · data 폴더 · CSV · 엑셀 파일, 사람 이름이나 연락처가 든 파일이 있으면 멈추고 알려 줘. 2. 문제가 없으면 원격 저장소를 7단계에서 만든 내 비공개 리포 주소로 연결하고 main 브랜치만 push 해 줘. 3. 로그인 창이 뜨면 내가 브라우저에서 로그인할게. 비밀번호나 토큰을 대화창에 묻지 마.
확인

GitHub 리포 화면을 새로고침하면 코드 · 설정 파일만 보이고 데이터 · .env 는 없다. test 브랜치는 올라가지 않았다.

7단계에서 gh 로 로그인했으면 묻지 않고 올라갑니다그래도 브라우저 로그인 창이 뜨면 Git for Windows 의 로그인 도우미(Git Credential Manager)입니다. Sign in with your browser → 허용하면 다음부터는 묻지 않습니다.
주의이미 올라갔다면 리포에서 지우는 것으로 끝나지 않습니다 — 키는 새로 발급받고, 개인정보는 강사에게 바로 알립니다.

PART 5GitHub 에서 내 업무에 맞는 스킬 · 에이전트 찾기

GitHub 은 올리는 곳이면서 남이 만든 스킬 · 에이전트 · 규칙을 찾는 곳입니다. 검색창에 손으로 넣는 대신, 내 업무를 적어 주면 Claude 가 검색하고 아래 기준으로 비교해 가장 맞는 것을 골라 줍니다.

9

내 업무에 맞는 것 찾기

기준보는 곳뜻
별 (Star)저장소 오른쪽 위 숫자「좋다」고 표시한 사람 수. 많을수록 검증된 편 — 다만 오래된 인기일 수 있다
포크 (Fork)별 옆 숫자가져가서 고쳐 쓴 사람 수 — 실제로 쓰였다는 신호
최근 업데이트파일 목록 위 마지막 커밋 날짜몇 달 넘게 멈췄으면 지금 Claude Code 와 안 맞을 수 있다
이슈위 탭 Issues문제 신고에 답이 오가면 관리되는 저장소
라이선스오른쪽 About 의 LicenseMIT · Apache 등 — 회사에서 써도 되는지
README첫 화면 아래 설명무엇을 하는지 · 설치법 · 예시가 있는지
방법

<내 업무 내용> 에 내가 하는 일을 한두 줄로 적어 붙여넣습니다. 무엇을 · 얼마나 자주 · 결과물이 무엇인지 적을수록 잘 맞는 것을 찾습니다.

내 업무에 가장 맞는 Claude Code 스킬 · 에이전트를 GitHub 에서 찾아 줘. 아무것도 내려받지 마. 내 업무: <내 업무 내용 — 예: 매주 월요일 센터별 매출 엑셀을 모아 요약 보고서를 쓴다> 1. 내 업무에서 영어 검색어 2~3개를 뽑아 보여 줘. 2. gh 로 검색해 줘 — 스킬은 gh search code 「filename:SKILL.md 검색어」, 에이전트는 「path:.claude/agents 검색어」, 저장소는 gh search repos 「검색어 claude」. 후보는 5개까지. 3. 후보마다 별 · 포크 · 마지막 업데이트 날짜 · 열린 이슈 수 · 라이선스 · README 설치법 · 내 업무와 맞는 점을 표로 정리해 줘. 4. 내 업무에 가장 적합한 것 하나를 이유와 함께 골라 주고, 저장소 주소와 받을 스킬(또는 에이전트) 이름을 알려 줘. 5. 맨 끝에 쓴 검색어를 「검색어: …」 한 줄로 따로 적어 줘.
확인

후보 비교표가 나오고, 받을 것 하나(저장소 주소 · 스킬 이름)와 「검색어:」 줄을 메모장에 적었다. Claude 의 추천과 달라도 됩니다 — 고르는 것은 사람.

맞는 것이 없다고 나오면업무를 더 넓게(예: 「매출 보고서」 → 「엑셀 요약」) 다시 적거나, 「검색어를 바꿔 한 번 더 찾아 줘」라고 합니다. 「검색어:」 줄은 11단계 스크립트가 매일 같은 검색을 하는 데 씁니다.
10

받아서 써 보기

방법
  1. <고른 저장소 주소> 와 <스킬 이름> 두 곳을 9단계 결과로 바꿔 붙여넣습니다. 처음엔 폴더 안에 SKILL.md 한 파일만 있는 것이 좋습니다 — 하위 폴더가 딸린 스킬은 그 파일만 받으면 일부만 동작합니다.
    <고른 저장소 주소> 에서 <스킬 이름> 스킬(또는 에이전트)을 이 폴더의 .claude 에 넣으려고 해. 저장소 전체를 내려받지 말고 그 파일만 받아. 1. 먼저 그 파일 내용을 읽고, 명령 실행 · 바깥 주소로 보내기 · 키나 비밀번호 요구 · 파일 지우기 같은 위험한 줄이 있는지 찾아서 보여 줘. 있으면 넣지 말고 멈춰. 2. 괜찮으면 스킬은 .claude/skills/<이름>/SKILL.md, 에이전트는 .claude/agents/<이름>.md 모양으로 넣어 줘. 3. 무엇을 넣었는지, 어떻게 부르는지 한 줄로 알려 줘.
  2. exit → claude 로 다시 켜고 /skills(에이전트면 「쓸 수 있는 에이전트 목록 보여 줘」)로 확인 → 한 번 불러 봅니다.
확인

목록에 받은 것이 보이고, 한 번 불러 결과가 나왔다.

.claude 에 넣을 때 허락 창이 한 번 더 뜹니다Claude Code 가 설정 폴더는 따로 지키기 때문입니다. 넣을 파일 이름이 .claude/skills/<이름>/SKILL.md 모양인지 보고 허용합니다.
주의받은 스킬은 연습 폴더에만 넣고 써 봅니다. 업무 폴더에 넣는 것은 며칠 써 보고 믿을 수 있을 때.

PART 6매일 돌릴 스크립트 — 9단계 검색을 프로그램으로

9단계 검색을 스크립트로 만들면, 12단계의 작업 스케줄러가 매일 아침 대신 돌리고 슬랙으로 알려 줄 수 있습니다. 결과는 구글 드라이브의 내 작업 폴더 이름 폴더에도 올려 두어, PC 가 꺼져 있어도 17단계 클라우드 루틴이 언제든 읽게 합니다.

11

내 업무 스킬 찾는 스크립트 · 드라이브에 올리기

방법

<검색어> 를 9단계 「검색어:」 줄로 바꿔 붙여넣습니다.

내 업무에 맞는 Claude 스킬 · 에이전트 저장소를 매일 찾는 Python 스크립트 gh_skills.py 를 이 폴더에 만들어 줘. - Python 표준 라이브러리만 쓴다. 키 · 로그인 없이 GitHub 검색 API(api.github.com/search/repositories)를 부른다. User-Agent 머리말을 넣는다. - 검색어는 스크립트 맨 위 KEYWORDS 에 둔다: <검색어>. 검색어마다 「검색어 claude」로 한 번씩만 부른다(최근 30일 안에 업데이트 · 별 많은 순 · 20개). 3개를 넘기지 않는다. - 저장소 이름 · 별 · 포크 · 마지막 업데이트 날짜 · 라이선스 · 설명 · 주소를 모아, 같은 저장소는 한 번만 남긴다. - 결과는 별 많은 순으로 data\깃허브_스킬.csv (UTF-8 BOM) 에 저장한다. data 폴더가 없으면 만든다. - 이미 본 저장소 이름은 data\seen.txt 에 쌓고, 이번에 처음 본 저장소 수를 센다. - 같은 CSV 를 구글 드라이브 데스크톱 앱의 「내 드라이브」 안 <작업 폴더 이름> 폴더에도 복사한다. 작업 폴더 이름은 이 Git 저장소 최상위 폴더 이름(git rev-parse --show-toplevel)이고, 그 폴더가 드라이브에 없으면 만든다. - 실행할 때마다 data\log.txt 에 「날짜 시각 · 전체 N건 · 새 M건 · 드라이브 OK/실패」 한 줄을 덧붙인다. 드라이브 복사가 실패해도 스크립트는 멈추지 않는다. 만들기 전에 이 PC 의 「내 드라이브」 경로를 찾아서 보여 줘. 구글 드라이브 데스크톱 앱이 없거나 로그인 전이면 멈추고 알려 줘. 다 만들면 한 번 실행해서 별 많은 상위 10개를 표로 보여 주고, gh_skills.py 만 「스킬 저장소 검색 스크립트」 메시지로 커밋해 줘.
확인
  1. 상위 10개 표가 나오고 data\깃허브_스킬.csv · data\log.txt 가 생겼다. git status 에 data 가 없다(1단계 제외 목록).
  2. 브라우저 drive.google.com → 내 드라이브 → 내 작업 폴더 이름 폴더에 깃허브_스킬.csv 가 있다.
코드는 GitHub, 데이터는 구글 드라이브스크립트(gh_skills.py)는 8단계 리포로, 결과 데이터(CSV)는 드라이브로 갑니다. 드라이브에 있으면 PC 가 꺼져 있어도 클라우드 루틴 · 다른 PC · 폰에서 언제든 열 수 있습니다. 개인정보가 든 데이터는 드라이브에도 올리지 않습니다.
구글 드라이브 데스크톱 앱이 없으면google.com/drive/download 에서 설치 → 회사 계정으로 로그인 → 탐색기에 「Google Drive」 가 보이면 다시 붙여넣습니다.
주의키 없는 검색은 1분에 10번까지입니다. 한 번 실행에 검색어 수만큼(3번 이하)만 부르니 충분하지만, 반복문으로 계속 검색하게 만들지 않습니다.

PART 7작업 스케줄러 — 내 PC 에서 정해진 시각에

12

정해진 시각에 저절로

방법
gh_skills.py 를 매일 아침 9시에 이 PC 에서 저절로 돌리게 해 줘. 1. 이 폴더에 run.bat 을 만들어 줘. 영어(ASCII)만 쓰고 줄바꿈은 CRLF. 이 폴더로 이동한 뒤 python gh_skills.py 를 실행하게. 2. 윈도우 작업 스케줄러에 작업 이름 AX_gh_daily 로, 매일 09:00 에 run.bat 을 실행하도록 등록해 줘. 내 계정으로, 관리자 권한 없이. 3. 등록한 작업을 지금 한 번 실행하고, 끝나면 data\log.txt 마지막 줄과 작업의 마지막 실행 결과를 보여 줘. 4. run.bat 을 「예약 실행」 메시지로 커밋해 줘.
확인
  1. data\log.txt 줄이 하나 늘었다(새 저장소는 0건일 수 있습니다 — 방금 다 봤으니까요).
  2. 윈도우 시작 → 「작업 스케줄러」 → 작업 스케줄러 라이브러리에 AX_gh_daily 가 있고 마지막 실행 결과가 (0x0).
주의.bat 파일에는 한글을 쓰지 않습니다. 윈도우 콘솔에서 글자가 깨져 명령이 엉뚱하게 실행됩니다. 한글이 필요한 일은 .py 안에서 합니다.
실행할 때 검은 창이 잠깐 떴다 사라집니다정상입니다. 창을 숨기는 방법은 2step에서 다룹니다.
13

놓친 실행 · 절전 · 지우기

방법
  1. AX_gh_daily 작업 설정을 바꿔 줘. - 예약된 시간을 놓치면 가능한 빨리 실행 (StartWhenAvailable) - 작업을 실행하기 위해 절전 모드 종료 (WakeToRun) 바꾼 뒤 두 설정이 켜졌는지, 다음 실행 시각과 마지막 실행 결과를 보여 줘.
  2. 16단계(슬랙)까지 끝낸 뒤 실습 작업을 지웁니다.
    작업 스케줄러에서 AX_gh_daily 작업을 지워 줘. 지운 뒤 목록에 없는지 보여 줘.
확인

두 설정이 켜짐(True)으로 나왔고, 마지막에 작업 목록에서 AX_gh_daily 가 사라졌다.

주의작업 스케줄러는 PC 가 켜져 있고 내 계정으로 로그인한 동안만 돕니다. 꺼져 있던 날은 다음에 켤 때 한 번 돕니다(위 설정 덕분). PC 가 꺼져도 돌아야 하는 일은 17단계 클라우드 루틴입니다.
왜 지우나요남겨 두면 매일 검색이 돌고 슬랙에 메시지가 쌓입니다. 2step에서 AI 직원을 새로 등록합니다.

PART 8슬랙 웹훅 — 끝나면 알려 주기

내 슬랙 계정과 나만 있는 워크스페이스를 만들고, 그 채널로 스크립트가 보고하게 합니다. 내가 만든 워크스페이스라 앱 설치를 막는 관리자가 없습니다.

14

슬랙 가입 · 내 워크스페이스

방법
  1. slack.com/get-started → 회사 메일을 넣고 계속 → 메일로 온 6자리 코드를 넣습니다.
  2. 「이미 있는 워크스페이스에 참여」 안내가 보여도 새 워크스페이스 만들기를 고릅니다.
  3. 워크스페이스 이름 = <내 이름>-ax · 내 이름 입력 · 팀원 초대는 건너뛰기.
  4. 「팀이 무슨 일을 하나요」처럼 첫 채널 이름을 물으면 알림. 유료 체험을 권하면 무료로 시작합니다.
  5. 데스크톱 앱이 없으면 브라우저로 써도 됩니다.
확인

왼쪽 위에 내 워크스페이스 이름, 채널 목록에 #알림 이 보이고 메시지를 쓸 수 있다.

주의회사가 이미 쓰는 슬랙 워크스페이스에 만들지 않습니다. 실습 메시지가 동료에게 갑니다.
15

웹훅 만들기

방법
  1. <내 이름> 만 바꿔 붙여넣습니다.
    슬랙 웹훅을 만들려고 해. 앱 설정(매니페스트)을 네가 만들어 주고, 나는 붙여넣기 · 허용만 할게. 1. 아래 내용으로 슬랙 앱 매니페스트를 JSON 으로 만들어 slack_app.json 으로 저장해 줘. - 앱 이름: <내 이름> 알림 - 권한: 웹훅(incoming-webhook) 하나만. 그 밖의 권한 · 기능은 넣지 마. 2. 그 내용을 클립보드에 복사해 줘(Set-Clipboard). 3. .env 파일이 없으면 만들고 SLACK_WEBHOOK_URL= 한 줄을 넣어 줘(값은 비워 둬). 제외 목록(.gitignore)에 .env 가 있는지도 확인해. 4. 내가 슬랙 화면에서 누를 순서를 짧게 알려 주고 멈춰. 웹훅 주소는 내가 .env 에 직접 붙여넣을 거니 대화창에 붙이라고 하지 마.
  2. api.slack.com/apps → Create New App → From a manifest → 워크스페이스 = 14단계에서 만든 것 → JSON 칸을 비우고 Ctrl+V → Next → Create.
  3. 왼쪽 Install App → Install to Workspace → 보낼 채널 = #알림 → 허용.
  4. 왼쪽 Incoming Webhooks → 아래 목록의 Webhook URL(https://hooks.slack.com/services/…) Copy → 왼쪽 탐색기에서 .env 를 열어 SLACK_WEBHOOK_URL= 뒤에 붙여넣고 저장(Ctrl+S).
확인

.env 에 SLACK_WEBHOOK_URL=https://hooks.slack.com/… 가 있고, git status 에 .env 가 나오지 않는다.

왜 마지막은 사람이 하나요슬랙은 웹훅 주소를 사람이 채널을 고르고 허용해야만 내줍니다. 그래서 Claude 는 설정 파일 · .env 칸까지 만들고, 허용 · 붙여넣기는 내가 합니다. 주소가 대화 기록에 남지 않는 것도 이 방법의 장점입니다.

보내기 · 스크립트에 붙이기

방법

<내 이름> 만 바꿔 붙여넣습니다.

확인

내 슬랙 #알림 채널에 메시지가 두 개(테스트 · 새 M건) 왔다. git status 에 .env 가 없다.

PART 9클라우드 루틴 — PC 가 꺼져도

작업 스케줄러는 내 PC 가 켜져 있어야 돕니다. 클라우드 루틴은 Claude 가 클라우드에서 정해진 시각에 돕니다. 대신 쓸 수 있는 것이 좁습니다.

루틴에 들어가는 기술

기술설명
클라우드 실행 환경예약 시각이 되면 클라우드에 Claude Code 세션이 새로 열려 지시문을 실행합니다. 내 PC 는 필요 없습니다.
커넥터claude.ai 에 연결해 둔 Google Drive(시트 포함) · Gmail · 캘린더 등을 그 세션이 씁니다. 내 Claude 계정에 연결된 것만 됩니다(basic 2step에서 연결한 구글 커넥터).
GitHub 리포루틴이 작업할 저장소를 고르라고 할 수 있습니다 — 8단계에서 만든 비공개 리포를 고릅니다.
예약매일 · 평일 · 매시처럼 반복할 시각을 정합니다.

제약 — 이것은 안 됩니다

제약그래서
시각은 UTC한국 시각에서 9시간을 뺍니다 (한국 아침 9시 = UTC 0시)
최소 1시간 간격분 단위 반복은 안 됩니다
바깥 사이트 접속이 막혀 있다(기본 환경 · 슬랙 웹훅 · 공공기관 사이트 등)수집 · 슬랙 전송은 루틴에 맡기지 않습니다 — 작업 스케줄러로

엑셀은 줄바꿈 없이 한 줄로 읽힌다데이터는 CSV · 구글 시트로
실행할 때마다 사용량이 든다실습 뒤 예약은 꺼 둡니다
