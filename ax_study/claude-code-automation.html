1

워크스페이스 · 프로젝트마다 Git 시작

방법
  1. VS Code 에서 평소 쓰는 워크스페이스를 열고 터미널에서 claude. 저장소는 워크스페이스 하나 + 프로젝트 폴더마다 하나씩 만듭니다 — 소스 제어 · 그래프가 저장소별로 나뉘어, 무엇을 고쳤는지와 어디로 되돌릴지 찾기 쉽습니다.
  2. [복사] → 붙여넣기 → Enter.
    지금 워크스페이스를 Git 으로 관리하고 싶어. 워크스페이스 자체(공용 .claude · 스크립트)에 저장소 하나, 그 안의 프로젝트 폴더마다 저장소를 하나씩 따로 만들 거야. 아래 순서로 하되, 저장(커밋)은 내가 확인한 뒤에만 해 줘. 1. 지금 폴더의 전체 경로와 바로 아래 폴더 목록을 폴더마다 파일 수와 함께 보여 줘. 이 폴더 바깥은 건드리지 마. 2. git --version 으로 Git 이 있는지 확인해. 없으면 멈추지 말고 네가 설치해: winget install --id Git.Git -e --source winget --accept-package-agreements --accept-source-agreements. winget 이 없거나 실패하면 git-for-windows 의 GitHub 최신 릴리스에서 64-bit.exe 설치 파일을 받아 /VERYSILENT /NORESTART 로 설치해. 관리자 허락 창이 뜨면 내가 누를게. 설치 직후 git 을 못 찾으면 이 대화가 끝날 때까지 C:\Program Files\Git\cmd\git.exe 전체 경로로 실행해. 나에게 껐다 켜라고 하지 말고 끝까지 이어서 해. 3. 이 폴더 · 하위 폴더 · 상위 폴더 중 이미 Git 저장소인 곳이 있으면 새로 만들지 말고 그 위치와 git status 만 보여 주고 멈춰. 4. 따로 저장소로 만들 프로젝트 폴더 후보(코드 · 스크립트가 있는 폴더)를 골라 이유와 함께 보여 줘. 연습용 git_practice 폴더(빈 메모.txt 하나)를 새로 만드는 것도 후보에 넣어. 내가 고를 때까지 기다려. 5. 저장소마다 제외 목록(.gitignore) 후보를 보여 줘. 기본은 .env, data/, *.csv, *.xlsx, *.xls 이고, 그 밖에 사람 이름 · 연락처 · 실적 데이터가 들어 있을 것 같은 폴더 · 파일도 이유와 함께 보여 줘. 워크스페이스 저장소의 제외 목록에는 따로 저장소가 되는 프로젝트 폴더도 넣어(저장소가 겹치지 않게). 그런 파일의 내용은 화면에 옮기지 마. 「선택」 후보는 내가 정할 때까지 넣지 마. 6. 내가 「좋아」라고 하면 저장소들을 만들고(기본 브랜치 main), 제외 목록을 저장소마다 .gitignore 로 저장해 줘. 7. 저장소마다 기록될 파일 목록(git status)을 보여 줘. 데이터 · 개인정보로 보이는 파일이 있으면 멈추고 알려 줘. 8. 내가 다시 「좋아」라고 하면 저장소마다 「처음 저장」 메시지로 커밋해 줘. 이름 · 메일이 설정돼 있지 않으면 나에게 한 번만 묻고 이 PC 의 Git 전체(--global)에 설정해 줘.
  3. 4번 후보에서 저장소로 만들 프로젝트를 고릅니다. 고르기 어려우면 git_practice 만 골라도 됩니다(3~5단계 연습용).
  4. 5번 제외 목록 후보를 읽고, 빼야 할 폴더가 더 있으면 말로 더합니다 → 「좋아」.
  5. 7번 기록될 파일 목록에 데이터 · 개인정보가 없으면 → 다시 「좋아」.
  6. 이름 · 메일을 물으면 답합니다. 메일은 6단계에서 GitHub 에 가입할 메일(회사 메일)과 같게 — 다르면 올린 커밋이 내 계정과 이어지지 않습니다.
확인

터미널에서 git --version 을 쳐서 번호가 나오는지 한 번 확인합니다. Git 을 방금 설치했다면 VS Code 창을 모두 닫았다가 다시 연 뒤에 칩니다.

주의한 번 기록된 파일은 나중에 제외 목록에 넣어도 기록에 남습니다. 그래서 저장 전에 두 번(5 · 7번) 확인합니다. 의심되면 일단 제외 목록에 넣습니다 — 빼는 것은 언제든 됩니다.
주의VS Code 왼쪽 소스 제어에 파란 「게시 Branch」 버튼이 보여도 누르지 않습니다. GitHub 에 올리는 일은 7 · 8단계에서 비공개 리포로 합니다.
「LF will be replaced by CRLF」 경고가 나오면Windows 에서 줄바꿈 형식을 맞춘다는 안내입니다. 오류가 아니고 파일 내용은 그대로입니다.
커밋 메시지 아래에 Co-Authored-By: Claude 줄이 붙어 있으면Claude 와 같이 만든 커밋이라는 표시입니다. 정상입니다.
Git 은 코드의 세이브 포인트 — 데이터 백업은 드라이브로제외 목록에 넣은 데이터는 Git 이 처음부터 기록하지 않습니다. 그래서 데이터를 지워도 소스 제어에 뜨지 않고, Git 으로 되살릴 수도 없습니다. 데이터까지 Git 에 넣으면 GitHub 로 같이 올라가고, 한 번 기록되면 지워도 남기 때문에 넣지 않습니다.

나중에 프로젝트 폴더를 새로 만들면Claude 에게 「이 폴더도 따로 저장소로 만들고, 워크스페이스 .gitignore 에 이 폴더를 넣어 줘」라고 합니다. 워크스페이스 제외 목록에 넣지 않으면 워크스페이스 저장소가 그 폴더를 「안에 든 저장소」로 잘못 기록합니다. 프로젝트가 아주 크면 첫 저장이 오래 걸리니 큰 데이터 폴더를 제외 목록에 넣습니다.

방법

저장소가 여러 개일 때 「소스 제어」 화면
번호보이는 것뜻
①저장소 목록저장소마다 한 줄. 예: work = 워크스페이스(공용 .claude · 스크립트) · data_analysis = 프로젝트 · git_practice = 연습용. 파란 테두리가 지금 고른 저장소
②줄마다 main저장소마다 브랜치가 따로 있습니다. 한 저장소에서 브랜치를 바꿔도 다른 저장소는 그대로입니다
③그래프 제목 옆 저장소 이름아래 그래프가 어느 저장소의 기록인지. 목록에서 다른 저장소를 누르면 그 저장소 기록으로 바뀝니다
3

저장 · 비교

방법
git_practice 폴더의 메모.txt 맨 끝에 「Git 연습: 첫 수정」 한 줄을 추가해 줘. git 명령은 git_practice 저장소에서만 실행하고, 다른 저장소 · 파일은 건드리지 마. 저장 전에 git diff 로 바뀐 곳을 보여 주고, 메모.txt 만 git add 해서 「연습: 첫 수정」 메시지로 커밋해 줘. 마지막에 git log --oneline -3 을 보여 줘.
확인

diff 에 +Git 연습: 첫 수정 이 보이고, 커밋이 하나 늘었다.

커밋 = 저장 지점게임의 세이브 포인트처럼 커밋마다 그 순간의 파일 상태가 남습니다. 메시지는 「무엇을 왜」를 짧게 — 나중에 목록만 봐도 찾을 수 있게.
VS Code 왼쪽 「소스 제어」 화면 읽는 법
번호보이는 것뜻
①아이콘 위 숫자 (예: 1)아직 커밋하지 않은 파일 수
②변경 사항 목록마지막 커밋 뒤에 바뀐 파일. 오른쪽 글자 M = 고침 · U = 새 파일 · D = 지움
③파란 「커밋」 버튼누르지 않습니다 — 커밋은 카드대로 Claude 에게 시킵니다
④파일 옆 되돌리기 화살표누르면 그 파일의 고친 내용이 바로 사라집니다. 누르지 않습니다
⑤그래프커밋 목록. 위가 최신이고, main 표시가 지금 내가 있는 자리
내가 시키지 않은 파일이 변경 사항에 있으면 그 파일을 눌러 무엇이 바뀌었는지 본 뒤 Claude 에게 「이 파일은 왜 바뀌었어? 아직 아무것도 하지 마」라고 묻습니다. 3단계 프롬프트는 git_practice 의 메모.txt 만 커밋하므로, 다른 파일이 남아 있는 것 자체는 정상입니다.
4

되돌리기

방법
git_practice 의 메모.txt 에서 그 줄을 일부러 「Git 연습: 실수」로 바꿔 「연습: 실수」 메시지로 커밋해 줘. 그다음 방금 커밋을 되돌려 줘. 기록은 지우지 말고 되돌리는 커밋을 새로 만들어(git revert). 그 파일 내용과 git log --oneline -4 를 보여 줘.
확인

파일이 「첫 수정」으로 돌아왔고, 목록 맨 위에 Revert "연습: 실수" 가 있다.

주의「기록까지 지우는 되돌리기」(git reset --hard)는 시키지 않습니다. 지운 기록은 다시 못 찾습니다.
4단계를 마친 뒤 「소스 제어」 화면
번호보이는 것뜻
①변경 내용이 비어 있음되돌리기까지 모두 커밋돼서 남은 변경이 없습니다. 아이콘 위 숫자도 사라집니다
②파란 「게시 Branch」 버튼변경이 없으면 커밋 버튼 대신 나옵니다. 누르지 않습니다 — GitHub 올리기는 7 · 8단계
③Revert "연습: 실수" + main되돌리기도 새 커밋 하나입니다. 맨 위가 지금 상태이고, 파일 내용은 「첫 수정」과 같습니다
④연습: 실수실수한 커밋이 지워지지 않고 남아 있습니다. 그래서 무엇을 잘못했는지 나중에도 볼 수 있습니다 — 이것이 git revert 가 안전한 이유입니다
5

브랜치

방법
git_practice 저장소에 test 브랜치를 만들어 거기서 메모.txt 에 「브랜치에서 쓴 줄」을 추가하고 커밋해 줘(그 파일만 · 다른 저장소는 건드리지 마). main 으로 돌아와서 그 파일에 그 줄이 없는 것을 보여 주고, git diff main test 로 두 브랜치의 차이를 보여 줘. 합치지는 마.
확인

git branch 에 main · test, 지금은 main 이고 파일에 그 줄이 없다.

브랜치는 언제 쓰나요잘 돌고 있는 스크립트를 크게 고쳐 볼 때. test 에서 고쳐 보고, 괜찮으면 main 에 합치고, 아니면 버립니다. main 은 그동안 멀쩡합니다.
주의브랜치를 바꾸기 전에는 저장 안 한 수정이 없어야 합니다. 「저장 안 한 변경이 있다」고 하면 먼저 커밋하거나 Claude 에게 「어떻게 할지 물어봐 줘」라고 합니다.
5단계를 마친 뒤 화면
번호보이는 것뜻
①왼쪽 그래프에 test 커밋이 없음그래프는 기본으로 지금 있는 브랜치(main)만 보여 줍니다. test 커밋이 사라진 것이 아닙니다
②+브랜치에서 쓴 줄git diff main test 결과. main 과 비교해 test 에만 이 한 줄(+)이 더 있습니다
③브랜치 상태 * main · test브랜치가 두 개이고, * 표시가 지금 있는 브랜치(main)입니다. 두 브랜치는 합치지 않았습니다
직접 확인해 보기 VS Code 왼쪽 아래 상태 표시줄의 브랜치 이름(main)을 눌러 test 로 바꾸면 파일에 그 줄이 다시 나타나고 그래프에도 test 커밋이 보입니다. 다 봤으면 다시 main 으로 돌아옵니다.
② GitHub 6~10단계 · 40분

가입

올리기 (push)

방법
GitHub 에 올리기 전에 확인부터 해 줘. 1. 올라갈 파일 목록(git ls-files)을 보여 줘. .env · data 폴더 · CSV · 엑셀 파일, 사람 이름이나 연락처가 든 파일이 있으면 멈추고 알려 줘. 2. 문제가 없으면 git remote -v 로 원격 저장소부터 봐. 없으면 7단계에서 만든 내 비공개 리포 주소(https://github.com/<내 아이디>/<리포 이름>.git)로 git remote add origin 하고, 이미 있는데 그 주소가 아니면 바꾸지 말고 멈춰서 주소를 보여 줘. 맞으면 main 브랜치만 git push -u origin main 해 줘. 3. 로그인 창이 뜨면 내가 브라우저에서 로그인할게. 비밀번호나 토큰을 대화창에 묻지 마. 4. push 가 끝나면 gh api repos/<내 아이디>/<리포 이름>/commits/main --jq .author.login 으로 최신 커밋이 내 GitHub 아이디와 이어졌는지 보여 줘(아이디는 gh api user --jq .login, 리포 이름은 gh repo view --json name 으로 직접 확인해 — 대화 기록에서 찾지 마). 비어 있거나 null 이면 Git 메일과 GitHub 메일이 다른 것이니 git config --global user.email 값과 함께 알려 줘.
확인

GitHub 리포 화면을 새로고침하면 코드 · 설정 파일만 보이고 데이터 · .env 는 없다. 4번 결과에 내 GitHub 아이디가 나온다(비어 있거나 null 이면 6단계 팁).

PART 7작업 스케줄러 — 내 PC 에서 정해진 시각에

12

정해진 시각에 저절로

방법
gh_skills.py 를 매일 아침 9시에 이 PC 에서 저절로 돌리게 해 줘. 1. 이 폴더에 run.bat 을 만들어 줘. 영어(ASCII)만 쓰고 줄바꿈은 CRLF. 이 폴더로 이동한 뒤 python gh_skills.py 를 실행하게. 2. 윈도우 작업 스케줄러에 작업 이름 AX_gh_daily 로, 매일 09:00 에 run.bat 을 실행하도록 등록해 줘. 내 계정으로, 관리자 권한 없이. 3. 등록한 작업을 지금 한 번 실행하고, 끝나면 data\log.txt 마지막 줄과 작업의 마지막 실행 결과를 보여 줘. 4. run.bat 을 「예약 실행」 메시지로 커밋해 줘.
확인
  1. data\log.txt 줄이 하나 늘었다(새 저장소는 0건일 수 있습니다 — 방금 다 봤으니까요).
  2. 윈도우 시작 → 「작업 스케줄러」 → 작업 스케줄러 라이브러리에 AX_gh_daily 가 있고 마지막 실행 결과가 (0x0).
주의.bat 파일에는 한글을 쓰지 않습니다. 윈도우 콘솔에서 글자가 깨져 명령이 엉뚱하게 실행됩니다. 한글이 필요한 일은 .py 안에서 합니다.
실행할 때 검은 창이 잠깐 떴다 사라집니다정상입니다. 창을 숨기는 방법은 2step에서 다룹니다.
