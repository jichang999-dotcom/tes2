PART 2Git — 저장 · 비교 · 되돌리기

Git 을 켜도 아무것도 올라가지 않습니다Git 은 내 PC 안에서만 기록합니다. 인터넷에 올라가는 것은 5단계 push 때뿐이고, 그때도 Git 을 켠 폴더 안의, 제외하지 않은 파일만 올라갑니다. 그래서 Git 은 실습 폴더 하나에서만 켭니다 — 워크스페이스 맨 위에서 켜면 다른 프로젝트까지 기록 대상이 됩니다.
1

실습 폴더 auto 를 Git 으로

방법
  1. 윈도우 탐색기에서 초급 작업 폴더(예: claude_work) 안에 auto 폴더를 새로 만듭니다.
  2. VS Code 에서 [파일] → [폴더 열기] → auto 를 엽니다.
  3. 터미널에서 claude → 폴더 신뢰를 물으면 Yes.
  4. [복사] → 붙여넣기 → Enter.
    지금 폴더에서 Git 을 시작해 줘. 1. 먼저 지금 폴더의 전체 경로를 보여 줘. 폴더 이름이 auto 가 아니면 멈추고 알려 줘. 이 폴더 바깥은 건드리지 마. 2. git --version 으로 Git 이 있는지 확인해. 없으면 설치하지 말고 멈춘 뒤 설치 방법만 알려 줘. 3. 이 폴더를 Git 저장소로 만들어 줘. 기본 브랜치 이름은 main. 4. .gitignore 를 만들어 아래 다섯 줄을 넣어 줘. .env data/ *.csv *.xlsx *.xls 5. README.md 를 만들어 「Advance 교육 실습 폴더」 한 줄을 쓰고, .gitignore 와 README.md 만 「처음 저장」 메시지로 커밋해 줘. 커밋할 때 이름 · 메일이 설정돼 있지 않으면 나에게 먼저 물어보고, 이 폴더에만(--local) 설정해 줘. 6. git status 와 git log --oneline 을 보여 줘.
확인

경로 끝이 \auto 이고, git log 에 커밋 1개(「처음 저장」), 왼쪽 탐색기에 .gitignore · README.md 가 보인다.

.gitignore 는 「기록하지 않을 것」 목록.env(10단계 웹훅 주소) · data/(7단계 수집 결과) · CSV · 엑셀은 처음부터 기록 대상에서 뺍니다. 한 번 기록된 파일은 나중에 목록에 넣어도 기록에 남아 있습니다 — 그래서 맨 처음에 만듭니다.
2

고치고 · 비교하고 · 저장

방법
README.md 에 「목적: 교육청 학원 공고를 매일 모아 슬랙으로 받는다」 한 줄을 추가해 줘. 저장(커밋) 전에 무엇이 바뀌었는지 git diff 로 보여 주고, 「목적 추가」 메시지로 커밋해 줘. 마지막에 git log --oneline 을 보여 줘.
확인

diff 에 +목적: … 줄이 보이고, 커밋이 2개가 됐다.

커밋 = 저장 지점게임의 세이브 포인트처럼, 커밋마다 그 순간의 파일 상태가 남습니다. 메시지는 「무엇을 왜 바꿨나」를 짧게 씁니다 — 나중에 목록만 봐도 찾을 수 있게.
3

되돌리기 · 브랜치

방법
  1. 되돌리기 — 일부러 틀리게 고친 뒤 되돌립니다.
    README.md 의 목적 줄을 일부러 「목적: 아무거나」로 바꿔 「실수」 메시지로 커밋해 줘. 그다음 방금 커밋을 되돌려 줘. 기록은 지우지 말고 되돌리는 커밋을 새로 만들어(git revert). README.md 내용과 git log --oneline 을 보여 줘.
  2. 브랜치 — 원본을 건드리지 않고 따로 고쳐 봅니다.
    test 브랜치를 만들어 거기서 README.md 에 「메모: 브랜치에서 쓴 줄」을 추가하고 커밋해 줘. main 으로 돌아와서 README.md 에 그 줄이 없는 것을 보여 주고, git diff main test 로 두 브랜치의 차이를 보여 줘. 합치지는 마.
확인

README.md 의 목적 줄이 원래 문장으로 돌아왔고, git branch 에 main · test 두 개가 있다. 지금 있는 곳은 main.

주의「기록까지 지우는 되돌리기」(git reset --hard)는 시키지 않습니다. 지운 기록은 다시 못 찾습니다. 되돌릴 때는 오늘처럼 되돌리는 커밋을 새로 만드는 방식(revert)을 씁니다.
브랜치는 언제 쓰나요잘 돌고 있는 스크립트를 크게 고쳐 볼 때. test 에서 고쳐 보고, 괜찮으면 main 에 합치고, 아니면 버립니다. main 은 그동안 멀쩡합니다.

4

가입 · 비공개 리포

방법
  1. github.com/signup 에서 회사 메일로 가입합니다. 이미 계정이 있으면 로그인만.
  2. 오른쪽 위 + → New repository.
  3. Repository name = auto-practice · Private 선택 · 「Add a README file」 은 체크하지 않습니다 (1단계에서 이미 만들었습니다).
  4. Create repository → 화면에 뜬 주소(https://github.com/<내 아이디>/auto-practice.git)를 복사해 둡니다.
확인

리포 이름 옆에 Private 표시가 있고, 빈 리포 안내 화면이 보인다.

주의Public 으로 만들지 않습니다. 공개 리포는 검색으로 누구나 봅니다. 실수로 키 · 개인정보가 올라가면 지워도 남은 복사본을 회수할 수 없습니다.
5

올리기 (push)

방법

<리포 주소> 를 4단계에서 복사한 주소로 바꿔 붙여넣습니다.

GitHub 에 올리기 전에 확인부터 해 줘. 1. 올라갈 파일 목록(git ls-files)을 보여 줘. .env · data 폴더 · CSV · 엑셀 파일, 사람 이름이나 연락처가 든 파일이 있으면 멈추고 알려 줘. 2. 문제가 없으면 원격 저장소를 <리포 주소> 로 연결하고 main 브랜치만 push 해 줘. 3. 로그인 창이 뜨면 내가 브라우저에서 로그인할게. 비밀번호나 토큰을 대화창에 묻지 마.
확인

GitHub 리포 화면을 새로고침하면 .gitignore · README.md 두 파일만 보이고, 커밋 수가 4~5개다.

처음 한 번 브라우저 로그인 창이 뜹니다Git for Windows 에 들어 있는 로그인 도우미(Git Credential Manager)입니다. Sign in with your browser → GitHub 에서 허용하면 다음부터는 묻지 않습니다.
주의올리기 전 목록에 데이터 · 개인정보가 있으면 올리지 않고 멈춥니다. 이미 올라갔다면 리포에서 지우는 것으로 끝나지 않습니다 — 웹훅 주소 같은 키는 새로 발급받고, 개인정보는 강사에게 바로 알립니다.

등록하고 말로 한 번

방법
  1. Claude Code 에서 exit 로 나옵니다.
  2. 같은 터미널에 붙여넣고 Enter. 윈도우는 앞에 cmd /c 가 있어야 실행됩니다.
    claude mcp add playwright -- cmd /c npx -y @playwright/mcp@latest
  3. claude 로 다시 켜고 /mcp 를 입력해 playwright 가 connected 인지 봅니다.
  4. [복사] → 붙여넣기.
    Playwright MCP 로 브라우저를 열어 서울시교육청 홈페이지(sen.go.kr)의 고시 · 공고 게시판에서 「학원」을 검색해 줘. 최근 5건의 제목 · 등록일 · 링크를 표로 보여 줘. 글 본문은 열지 말고, 로그인이나 개인정보 입력 화면이 나오면 멈춰.
확인

새 크롬 창이 저절로 열려 검색하고, Claude Code 에 5줄 표가 나온다.

왜 이 게시판인가요초급 체험 6단계에서 robots.txt 로 가져와도 되는지 확인한 곳입니다. 다른 사이트를 쓸 때는 그 확인부터 다시 합니다.
주의Playwright 창은 내 평소 크롬과 따로 뜨는 전용 창입니다. 그 창에서 로그인한 것은 이 PC 에 남습니다 — 공용 PC 라면 끝난 뒤 그 창에서 로그아웃합니다.
7

스크립트로 굳히기

방법
방금 한 일을 매일 돌릴 수 있는 Python 스크립트 collect.py 로 만들어 줘. - 브라우저 없이 되는 방법을 먼저 써. Python 표준 라이브러리만 쓴다. 안 되면 멈추고 이유를 알려 줘. - 결과: data\학원공고.csv (제목 · 등록일 · 링크, UTF-8 BOM). data 폴더가 없으면 만든다. - 실행할 때마다 data\log.txt 에 「날짜 시각 · N건」 한 줄을 덧붙인다. - 게시판에는 목록 1페이지만 한 번 요청한다. 다 만들면 python collect.py 를 한 번 실행하고, collect.py 만 「수집 스크립트」 메시지로 커밋해 줘.
확인

data\학원공고.csv 에 공고가 들어 있고, data\log.txt 에 한 줄이 생겼다. git status 에 data 가 나오지 않는다(제외 목록 덕분).

왜 브라우저 없이 먼저인가요브라우저를 띄우면 느리고, 설치(약 150MB)가 필요하고, 화면이 조금만 바뀌어도 깨집니다. 목록이 브라우저 없이 받아지면 그게 가장 튼튼합니다. 6단계 MCP 는 어떻게 생긴 화면인지 알아내는 데 썼습니다.

PART 5작업 스케줄러 — 내 PC 에서 정해진 시각에

8

정해진 시각에 저절로

방법
collect.py 를 매일 아침 9시에 이 PC 에서 저절로 돌리게 해 줘. 1. 이 폴더에 run.bat 을 만들어 줘. 영어(ASCII)만 쓰고 줄바꿈은 CRLF. 이 폴더로 이동한 뒤 python collect.py 를 실행하게. 2. 윈도우 작업 스케줄러에 작업 이름 AX_notice_daily 로, 매일 09:00 에 run.bat 을 실행하도록 등록해 줘. 내 계정으로, 관리자 권한 없이. 3. 등록한 작업을 지금 한 번 실행하고, 끝나면 data\log.txt 마지막 줄과 작업의 마지막 실행 결과를 보여 줘. 4. run.bat 을 「예약 실행」 메시지로 커밋해 줘.
확인
  1. data\log.txt 줄이 하나 늘었다.
  2. 윈도우 시작 → 「작업 스케줄러」 → 왼쪽 작업 스케줄러 라이브러리에 AX_notice_daily 가 있고, 마지막 실행 결과가 (0x0).
주의.bat 파일에는 한글을 쓰지 않습니다. 한글이 들어가면 윈도우 콘솔에서 글자가 깨져 명령이 엉뚱하게 실행됩니다. 한글이 필요한 일은 .py 안에서 합니다.
실행할 때 검은 창이 잠깐 떴다 사라집니다정상입니다. 창을 숨기는 방법은 체험 편에서 다룹니다.
9

놓친 실행 · 절전 깨우기

방법
AX_notice_daily 작업 설정을 바꿔 줘. - 예약된 시간을 놓치면 가능한 빨리 실행 (StartWhenAvailable) - 작업을 실행하기 위해 절전 모드 종료 (WakeToRun) 바꾼 뒤 두 설정이 켜졌는지, 다음 실행 시각과 마지막 실행 결과를 보여 줘.
확인

두 설정이 켜짐(True)으로 나오고, 다음 실행 시각이 내일(또는 오늘) 09:00 이다.

주의작업 스케줄러는 PC 가 켜져 있고 내 계정으로 로그인한 동안만 돕니다. 꺼져 있던 날은 다음에 켤 때 한 번 돕니다(위 설정 덕분). PC 가 꺼져도 돌아야 하는 일은 12단계 클라우드 루틴입니다.

PART 6슬랙 웹훅 — 끝나면 알려 주기

10

끝나면 슬랙으로

방법
  1. 빈 칸부터 만듭니다.
    이 폴더에 .env 파일을 만들고 SLACK_WEBHOOK_URL= 한 줄만 넣어 줘(값은 비워 둬). .gitignore 에 .env 가 있는지도 확인해 줘.
  2. 왼쪽 탐색기에서 .env 를 열고 = 뒤에 강사가 쪽지로 준 웹훅 주소를 붙여넣은 뒤 저장(Ctrl+S)합니다.
  3. <내 이름> 만 바꿔 붙여넣습니다.
    .env 의 SLACK_WEBHOOK_URL 로 「<내 이름> 테스트」 한 줄을 보내 줘. 웹훅 주소는 화면에 출력하지 마. 보내지면 collect.py 끝에 「학원 공고 N건 수집 (<내 이름>)」을 같은 웹훅으로 보내는 코드를 넣어 줘. Python 표준 라이브러리만 쓰고, .env 는 직접 읽고, 주소가 비어 있으면 보내지 않고 넘어가게. python collect.py 를 한 번 실행하고, collect.py 를 「슬랙 보고」 메시지로 커밋해 줘.
확인

교육용 채널에 내 이름이 붙은 메시지가 두 개(테스트 · N건 수집) 왔다. git status 에 .env 가 나오지 않는다.

주의웹훅 주소를 아는 사람은 누구나 그 채널에 글을 쓸 수 있습니다. 주소는 .env 파일에만 두고 채팅 · 코드 · 문서에 붙이지 않습니다.
이제 8단계 예약도 슬랙으로 보고합니다내일 아침 9시에 작업이 돌면 채널에 「N건 수집」이 옵니다 — 11단계에서 작업을 지우기 전까지.
