PART 2내 워크스페이스를 Git 으로

Git 을 켜도 아무것도 올라가지 않습니다Git 은 내 PC 안에서만 기록합니다. 인터넷에 올라가는 것은 8단계 push 때뿐이고, 그때도 제외 목록에 없는 파일만 올라갑니다.
1

워크스페이스에서 Git 시작

방법
  1. VS Code 에서 평소 쓰는 워크스페이스(예: claude_work)를 열고 터미널에서 claude.
  2. [복사] → 붙여넣기 → Enter.
    지금 워크스페이스를 Git 으로 관리하고 싶어. 아래 순서로 하되, 저장(커밋)은 내가 확인한 뒤에만 해 줘. 1. 지금 폴더의 전체 경로와 바로 아래 폴더 목록을 보여 줘. 이 폴더 바깥은 건드리지 마. 2. git --version 으로 Git 이 있는지 확인해. 없으면 설치하지 말고 멈춘 뒤 설치 방법만 알려 줘. 3. 이미 Git 저장소면 새로 만들지 말고 git status 만 보여 주고 멈춰. 4. 제외 목록(.gitignore) 후보를 보여 줘. 기본은 .env, data/, *.csv, *.xlsx, *.xls 이고, 그 밖에 사람 이름 · 연락처 · 실적 데이터가 들어 있을 것 같은 폴더 · 파일도 후보로 골라 이유와 함께 보여 줘. 5. 내가 「좋아」라고 하면 Git 저장소로 만들고(기본 브랜치 main), 제외 목록을 .gitignore 로 저장해 줘. 6. 기록될 파일 목록(git status)을 보여 줘. 데이터 · 개인정보로 보이는 파일이 있으면 멈추고 알려 줘. 7. 내가 다시 「좋아」라고 하면 「처음 저장」 메시지로 커밋해 줘. 이름 · 메일이 설정돼 있지 않으면 나에게 묻고 이 저장소에만(--local) 설정해 줘.
  3. 후보 목록을 읽고, 빼야 할 폴더가 더 있으면 말로 더합니다 → 「좋아」.
확인

git log --oneline 에 커밋 1개, git status 에 데이터 · 개인정보 파일이 없다.

주의한 번 기록된 파일은 나중에 제외 목록에 넣어도 기록에 남습니다. 그래서 저장 전에 두 번(4 · 6번) 확인합니다. 의심되면 일단 제외 목록에 넣습니다 — 빼는 것은 언제든 됩니다.
워크스페이스가 아주 크면첫 저장이 오래 걸립니다. 큰 데이터 폴더를 제외 목록에 넣거나, 워크스페이스 안의 프로젝트 폴더 하나만 Git 으로 시작해도 됩니다.

PART 3저장 · 되돌리기 · 브랜치

실제 업무 파일로 연습하지 않도록, 연습할 폴더를 내가 골라 그 안에서만 합니다.

2

연습 폴더 고르기

방법
  1. 저장 · 되돌리기 · 브랜치를 연습할 폴더를 고르려고 해. 이 워크스페이스의 하위 폴더 목록을 파일 수와 함께 보여 주고, 연습하기 좋은 폴더(실제 데이터 · 중요한 결과물이 없는 곳)를 추천해 줘. 아무것도 바꾸지 마.
  2. 하나를 고릅니다. 마땅한 곳이 없으면 탐색기에서 새 폴더(예: git_practice)를 만들고 빈 텍스트 파일 메모.txt 를 하나 넣습니다.
  3. Claude Code 에서 exit → VS Code 에서 [파일] → [폴더 열기] 로 고른 폴더를 열고 → claude.
확인

VS Code 왼쪽 위 폴더 이름이 고른 폴더다. 3~5단계는 이 창에서 합니다.

왜 그 폴더를 열고 켜나요Claude 는 켠 폴더를 기준으로 일합니다. 연습 폴더에서 켜면 그 바깥 파일을 건드릴 일이 줄고, 11단계에서 받은 스킬도 이 폴더에서 바로 보입니다. Git 기록은 1단계 저장소에 그대로 쌓입니다.
3

저장 · 비교

방법
이 폴더 안의 파일 하나를 골라(없으면 메모.txt 를 만들어) 맨 끝에 「Git 연습: 첫 수정」 한 줄을 추가해 줘. 이 폴더 바깥 파일은 건드리지 마. 저장 전에 git diff 로 바뀐 곳을 보여 주고, 이 폴더 안 파일만 git add 해서 「연습: 첫 수정」 메시지로 커밋해 줘. 마지막에 git log --oneline -3 을 보여 줘.
확인

diff 에 +Git 연습: 첫 수정 이 보이고, 커밋이 하나 늘었다.

커밋 = 저장 지점게임의 세이브 포인트처럼 커밋마다 그 순간의 파일 상태가 남습니다. 메시지는 「무엇을 왜」를 짧게 — 나중에 목록만 봐도 찾을 수 있게.
4

되돌리기

방법
3단계에서 고친 파일의 그 줄을 일부러 「Git 연습: 실수」로 바꿔 「연습: 실수」 메시지로 커밋해 줘. 그다음 방금 커밋을 되돌려 줘. 기록은 지우지 말고 되돌리는 커밋을 새로 만들어(git revert). 그 파일 내용과 git log --oneline -4 를 보여 줘.
확인

파일이 「첫 수정」으로 돌아왔고, 목록 맨 위에 Revert "연습: 실수" 가 있다.

주의「기록까지 지우는 되돌리기」(git reset --hard)는 시키지 않습니다. 지운 기록은 다시 못 찾습니다.
5

브랜치

방법
test 브랜치를 만들어 거기서 3단계 파일에 「브랜치에서 쓴 줄」을 추가하고 커밋해 줘(이 폴더 안 파일만). main 으로 돌아와서 그 파일에 그 줄이 없는 것을 보여 주고, git diff main test 로 두 브랜치의 차이를 보여 줘. 합치지는 마.
확인

git branch 에 main · test, 지금은 main 이고 파일에 그 줄이 없다.

브랜치는 언제 쓰나요잘 돌고 있는 스크립트를 크게 고쳐 볼 때. test 에서 고쳐 보고, 괜찮으면 main 에 합치고, 아니면 버립니다. main 은 그동안 멀쩡합니다.
주의브랜치를 바꾸기 전에는 저장 안 한 수정이 없어야 합니다. 「저장 안 한 변경이 있다」고 하면 먼저 커밋하거나 Claude 에게 「어떻게 할지 물어봐 줘」라고 합니다.

PART 4GitHub — 가입 · 리포 · 올리기

6

가입

방법
  1. github.com/signup → 회사 메일 · 비밀번호 · 사용자 이름(영문)을 넣습니다. 이미 계정이 있으면 로그인만.
  2. 메일로 온 인증 코드를 넣습니다.
  3. 로그인 뒤 오른쪽 위 프로필 → Settings → Password and authentication → 2단계 인증을 켭니다(휴대폰 인증 앱).
확인

오른쪽 위에 내 프로필 사진(기본 그림)이 보이고, 2단계 인증이 켜져 있다.

7

비공개 리포 만들기

방법
  1. 오른쪽 위 + → New repository.
  2. Repository name = 워크스페이스 이름(예: claude-work) · Private 선택 · 「Add a README file」 은 체크하지 않습니다(1단계에서 이미 저장소가 있습니다).
  3. Create repository → 화면의 주소(https://github.com/<아이디>/<이름>.git)를 복사해 둡니다.
확인

리포 이름 옆에 Private 표시가 있다.

주의Public 으로 만들지 않습니다. 공개 리포는 검색으로 누구나 봅니다. 실수로 키 · 개인정보가 올라가면 지워도 복사본을 회수할 수 없습니다.
8

올리기 (push)

방법

<리포 주소> 를 7단계 주소로 바꿔 붙여넣습니다.

GitHub 에 올리기 전에 확인부터 해 줘. 1. 올라갈 파일 목록(git ls-files)을 보여 줘. .env · data 폴더 · CSV · 엑셀 파일, 사람 이름이나 연락처가 든 파일이 있으면 멈추고 알려 줘. 2. 문제가 없으면 원격 저장소를 <리포 주소> 로 연결하고 main 브랜치만 push 해 줘. 3. 로그인 창이 뜨면 내가 브라우저에서 로그인할게. 비밀번호나 토큰을 대화창에 묻지 마.
확인

GitHub 리포 화면을 새로고침하면 코드 · 설정 파일만 보이고 데이터 · .env 는 없다. test 브랜치는 올라가지 않았다.

처음 한 번 브라우저 로그인 창이 뜹니다Git for Windows 의 로그인 도우미(Git Credential Manager)입니다. Sign in with your browser → 허용하면 다음부터는 묻지 않습니다.
주의이미 올라갔다면 리포에서 지우는 것으로 끝나지 않습니다 — 키는 새로 발급받고, 개인정보는 강사에게 바로 알립니다.

10

좋은 것 고르기

기준보는 곳뜻
별 (Star)저장소 오른쪽 위 숫자「좋다」고 표시한 사람 수. 많을수록 검증된 편 — 다만 오래된 인기일 수 있다
포크 (Fork)별 옆 숫자가져가서 고쳐 쓴 사람 수 — 실제로 쓰였다는 신호
최근 업데이트파일 목록 위 마지막 커밋 날짜몇 달 넘게 멈췄으면 지금 Claude Code 와 안 맞을 수 있다
이슈위 탭 Issues문제 신고에 답이 오가면 관리되는 저장소

PART 6유튜브 API 로 찾기 — GitHub 에서 고르기 어려울 때

GitHub 에서 무엇이 좋은지 감이 안 오면, 사람들이 많이 본 소개 영상에서 시작합니다. 영상 설명란에는 보통 GitHub 링크가 있습니다.

12

API 키 발급

방법
  1. console.cloud.google.com 에 회사 계정으로 들어가 위쪽에서 프로젝트를 고릅니다(없으면 새 프로젝트).
  2. 왼쪽 메뉴 API 및 서비스 → 라이브러리 → 「YouTube Data API v3」 검색 → 사용.
  3. API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → API 키.
  4. 만들어진 키의 키 수정 → API 제한사항 = 키 제한 → YouTube Data API v3 만 체크 → 저장.
  5. Claude Code 에 붙여넣기:
    이 폴더에 .env 파일이 없으면 만들고 YOUTUBE_API_KEY= 한 줄을 넣어 줘(값은 비워 둬). 이미 있으면 그 줄만 추가해. 제외 목록(.gitignore)에 .env 가 들어 있는지도 확인해 줘.
  6. 왼쪽 탐색기에서 .env 를 열고 = 뒤에 키를 붙여넣고 저장(Ctrl+S).
확인

.env 에 YOUTUBE_API_KEY= 뒤 값이 있고, git status 에 .env 가 나오지 않는다.

주의API 키는 .env 파일에만 둡니다. 채팅 · 코드 · 문서에 붙이지 않습니다. 「키 제한」을 꼭 겁니다 — 새어도 유튜브 검색밖에 못 하게.
프로젝트 만들기 버튼이 없으면회사 계정에서 프로젝트 생성이 막혀 있는 경우입니다. 강사에게 알리면 교육용 키로 진행합니다.

조회수 순으로 찾는 스크립트

방법
유튜브에서 Claude Code 스킬 · 에이전트 소개 영상을 찾는 Python 스크립트 yt_skills.py 를 이 폴더에 만들어 줘. - Python 표준 라이브러리만 쓴다. API 키는 .env 의 YOUTUBE_API_KEY 를 직접 읽고, 화면에 출력하지 않는다. - YouTube Data API v3 로 「Claude Code skills」 「Claude Code subagents」 두 검색어를 각각 한 번씩만 검색한다(최근 6개월 · 영상 · 검색어마다 25개). - 찾은 영상의 조회수 · 올린 날 · 채널 · 제목 · 영상 주소, 설명란에 있는 github.com 링크를 모은다. - 결과는 조회수 순으로 data\유튜브_스킬.csv (UTF-8 BOM) 에 저장한다. data 폴더가 없으면 만든다. - 이미 본 영상 ID 는 data\seen.txt 에 쌓고, 이번에 처음 본 영상 수를 센다. - 실행할 때마다 data\log.txt 에 「날짜 시각 · 전체 N건 · 새 M건」 한 줄을 덧붙인다. 다 만들면 한 번 실행해서 조회수 상위 10개를 표로 보여 주고, yt_skills.py 만 「유튜브 검색 스크립트」 메시지로 커밋해 줘.
확인

조회수 상위 10개 표가 나오고, data\유튜브_스킬.csv · data\log.txt 가 생겼다. git status 에 data 와 .env 가 없다.

표에서 고르는 법조회수만 보지 말고 올린 날 · 채널 · GitHub 링크를 같이 봅니다. 링크가 있으면 10단계 기준으로 그 저장소를 다시 확인합니다. 광고 · 낚시 영상도 섞여 있습니다 — 고르는 것은 사람.

PART 7작업 스케줄러 — 내 PC 에서 정해진 시각에

14

정해진 시각에 저절로

방법
yt_skills.py 를 매일 아침 9시에 이 PC 에서 저절로 돌리게 해 줘. 1. 이 폴더에 run.bat 을 만들어 줘. 영어(ASCII)만 쓰고 줄바꿈은 CRLF. 이 폴더로 이동한 뒤 python yt_skills.py 를 실행하게. 2. 윈도우 작업 스케줄러에 작업 이름 AX_yt_daily 로, 매일 09:00 에 run.bat 을 실행하도록 등록해 줘. 내 계정으로, 관리자 권한 없이. 3. 등록한 작업을 지금 한 번 실행하고, 끝나면 data\log.txt 마지막 줄과 작업의 마지막 실행 결과를 보여 줘. 4. run.bat 을 「예약 실행」 메시지로 커밋해 줘.
확인
  1. data\log.txt 줄이 하나 늘었다(새 영상은 0건일 수 있습니다 — 방금 다 봤으니까요).
  2. 윈도우 시작 → 「작업 스케줄러」 → 작업 스케줄러 라이브러리에 AX_yt_daily 가 있고 마지막 실행 결과가 (0x0).
주의.bat 파일에는 한글을 쓰지 않습니다. 윈도우 콘솔에서 글자가 깨져 명령이 엉뚱하게 실행됩니다. 한글이 필요한 일은 .py 안에서 합니다.
실행할 때 검은 창이 잠깐 떴다 사라집니다정상입니다. 창을 숨기는 방법은 2step에서 다룹니다.

놓친 실행 · 절전 · 지우기

방법
  1. AX_yt_daily 작업 설정을 바꿔 줘. - 예약된 시간을 놓치면 가능한 빨리 실행 (StartWhenAvailable) - 작업을 실행하기 위해 절전 모드 종료 (WakeToRun) 바꾼 뒤 두 설정이 켜졌는지, 다음 실행 시각과 마지막 실행 결과를 보여 줘.
  2. 18단계(슬랙)까지 끝낸 뒤 실습 작업을 지웁니다.
    작업 스케줄러에서 AX_yt_daily 작업을 지워 줘. 지운 뒤 목록에 없는지 보여 줘.
확인

두 설정이 켜짐(True)으로 나왔고, 마지막에 작업 목록에서 AX_yt_daily 가 사라졌다.

주의작업 스케줄러는 PC 가 켜져 있고 내 계정으로 로그인한 동안만 돕니다. 꺼져 있던 날은 다음에 켤 때 한 번 돕니다(위 설정 덕분). PC 가 꺼져도 돌아야 하는 일은 19단계 클라우드 루틴입니다.
왜 지우나요남겨 두면 매일 유튜브 사용량이 들고 슬랙에 메시지가 쌓입니다. 2step에서 AI 직원을 새로 등록합니다.
